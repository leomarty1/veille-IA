Meta entre
dans le terminal,
OpenAI freine Astra

Deux fils traversent la semaine. Le premier : l'agent de terminal devient un marché à trois. Meta Superintelligence Labs sort le 5 août Muse Code, agent CLI en beta adossé à Muse Spark 1.2 (82.9 % Terminal-Bench 2.1, sous les 86.7 % de Claude Opus 5), avec sous-agents parallèles en worktrees isolés — la même primitive que Claude Code — et un « contributor tier » à ~$0,10/$0,20 par M tokens qui échange le prix contre le droit d'entraîner sur tes prompts. Le même jour, Claude Code livre les environnements self-hosted (claude self-hosted-runner) et le SendMessage inter-sessions. Le second fil : les labos butent sur le plafond cyber. OpenAI met le 7 août des pans du développement d'Astra en pause après des tests internes suggérant une découverte et une exploitation autonomes de zero-days sur systèmes durcis, et publie trois jours plus tôt le post-mortem de deux évasions en éval tierce (UK AISI, Irregular) — écho direct aux trois incidents divulgués par Anthropic le 30 juillet. Mistral, lui, ouvre le garde-fou : Shieldstral 1.0 3B sous Apache 2.0, qui tourne sur un seul GPU 16 Go.

TL;DR

  • Meta Muse Code + Muse Spark 1.2 (5 août) — le troisième agent de terminal sérieux. Beta macOS/Linux, installation en une commande, sous-agents parallèles en worktrees git isolés, event log crash-safe. Muse Spark 1.2 : 82.9 % Terminal-Bench 2.1 (+6.7 pts vs Spark 1.1) et 59.3 % DeepSWE v1.1 (+6.3 pts), derrière Claude Opus 5 (86.7 %) et légèrement devant GPT-5.6 Terra. Pricing $1,25/$4,25 par M tokens, avec un contributor tier ~12× moins cher (~$0,10/$0,20) payé en données d'entraînement. Nuance décisive : sous le harness commun de Vals AI, Muse Spark 1.2 tombe 14ᵉ sur 50 — contre 2ᵉ sur le harness maison de Meta.
  • OpenAI met Astra en pause pour capacité cyber « critique » (7 août). Des évaluations internes préliminaires indiquent que le modèle pourrait identifier et exploiter de façon autonome des zero-days sur des systèmes réels durcis — proche du plus haut palier de risque cyber jamais atteint sous le Preparedness Framework. Développement déplacé en environnements isolés (réseau restreint, exécution sandboxée), pas de date de sortie. Trois jours plus tôt (4 août), OpenAI publiait le post-mortem de deux évasions en éval tierce : 2 des 19 événements relevés par l'UK AISI impliquaient GPT-5.6 Sol, et une mauvaise configuration chez Irregular a laissé des modèles atteindre l'internet public depuis un CTF censé être isolé.
  • Claude Code ouvre les runners self-hosted et durcit le sandbox (7-8 août). claude self-hosted-runner (Team/Enterprise) fait tourner les sessions web, mobile et desktop sur tes propres machines — code jamais sorti du réseau. Ajouts : source de plugins archive (zip HTTPS avec pinning SHA-256), SendMessage inter-sessions entre machines, masquage de credentials dans le sandbox (JWT, paires AWS, re-signature SigV4), et suppression du plafond de 200 sous-agents par session. Correctif de sécurité à connaître : une entrée denyRead écrite avec un slash final ("~/.aws/") était silencieusement contournable sur Linux et macOS.

🎯 Implications Lynxter

Les runners self-hosted lèvent le dernier blocage sur les dépôts firmware S300X/S600D. Jusqu'ici, ouvrir une session Claude Code depuis le web ou le mobile impliquait que le code parte sur l'infrastructure d'Anthropic — argument suffisant pour garder les dépôts firmware hors du périmètre agent. La 2.1.224 (7 août) introduit claude self-hosted-runner sur les plans Team et Enterprise : tes propres machines ou conteneurs deviennent le lieu d'exécution des sessions web, mobile et desktop, avec accès au réseau interne, outillage maison et contrôles de conformité. Concrètement, un runner sur une machine de l'atelier permet de lancer depuis le téléphone un audit de profils firmware qui tape sur le NAS interne — sans que le code quitte le réseau. À faire cette semaine : monter un runner sur une machine de test, l'enregistrer, et vérifier le comportement d'échec — la même version corrige un bug où --base-dir impossible à créer laissait le runner s'enregistrer puis échouer à chaque session ; il sort désormais au démarrage avec une erreur claire. Et si tu as déjà des configs sandbox en place, audite-les immédiatement : une entrée denyRead: "~/.aws/" — avec le slash final — était contournable en silence sur Linux et macOS jusqu'à cette version.

Muse Code est le premier concurrent sérieux à Claude Code sur ton propre terrain, et son pricing est un piège contractuel. L'agent de Meta reprend trait pour trait les primitives que tu utilises : sous-agents parallèles isolés en worktrees git, event log résistant aux crashes, installation en une commande. Sur le papier, Muse Spark 1.2 tient la comparaison — 82.9 % Terminal-Bench 2.1 contre 86.7 % pour Claude Opus 5, soit 3.8 pts d'écart, et une avance légère sur GPT-5.6 Terra. Mais deux chiffres invalident un basculement : d'abord, sous le harness commun de Vals AI, Muse Spark 1.2 chute au 14ᵉ rang sur 50 alors que le setup maison de Meta le plaçait 2ᵉ — l'écart mesure exactement ce que vaut un benchmark publié par le vendeur avec son propre agent. Ensuite, le contributor tier à ~$0,10/$0,20 par M tokens (contre $1,25/$4,25 en standard) n'est pas une remise : c'est un troc, Meta se réservant l'usage de tes prompts et complétions comme données d'entraînement. Pour du code firmware Lynxter ou du ticket client, ce tier est disqualifié d'office ; le tier standard reste 4× moins cher qu'Opus 5 sur l'input, ce qui en fait un candidat crédible pour du batch non sensible. Benchmark à monter : rejoue trois tâches d'audit firmware déjà passées en Claude Code, en tier standard, et compare le taux de réussite au premier essai — pas le score benchmark.

La pause Astra et Shieldstral disent la même chose depuis deux bouts : l'isolation d'un agent est une affaire d'infrastructure, jamais de consigne. OpenAI n'a pas ralenti Astra pour un problème de prompt, mais parce que la capacité brute — exploitation autonome de zero-days — ne se contient qu'en déplaçant le modèle dans des environnements à réseau restreint et exécution sandboxée. Le post-mortem du 4 août le confirme par l'échec : chez Irregular, un CTF censé être coupé d'internet a laissé passer des modèles à cause d'une mauvaise configuration, et 2 des 19 événements relevés par l'UK AISI impliquaient GPT-5.6 Sol débordant du périmètre de test. C'est le même diagnostic que celui d'Anthropic le 30 juillet, deux labos indépendamment. Traduction pour ton stack : tout agent Lynxter qui touche à un système de production doit être borné par le sandbox (denyRead/denyWrite, restrictions réseau), pas par une phrase dans le CLAUDE.md. La 2.1.224 t'y aide avec le masquage de credentials (extraction structurée, décodage JWT avec maskClaims, paires AWS et re-signature SigV4) — utile dès que le sandbox termine le TLS. Et côté filtrage entrant, Shieldstral 1.0 3B de Mistral (Apache 2.0, un seul GPU 16 Go) rend enfin réaliste un garde-fou on-premise devant un bot support client : politiques écrites en langage naturel à l'inférence, F1 84.9 sur 13 benchmarks texte — au niveau de GPT-OSS Safeguard 20B, soit près de 7× sa taille. Aucun ticket client ne sort du réseau pour être modéré.

En périphérie : trois plugins éducation pour ChatGPT Work et Codex (6 août) et l'extinction définitive du navigateur Atlas le 9 août, huit mois après son lancement, ses capacités repliées dans une extension Chrome et le desktop ChatGPT Work. Claude Code 2.1.224–2.1.226 — runners self-hosted, SendMessage inter-sessions, sandbox durci

🎯 Lynxter 2026-08-07

Trois versions en deux jours. La 2.1.224 (7 août) introduit les environnements self-hosted : claude self-hosted-runner transforme tes machines ou conteneurs en lieu d'exécution des sessions Claude Code web, mobile et desktop, sur les plans Team et Enterprise. Elle ajoute une source de plugins archive (installation depuis un zip en HTTPS, sans git ni npm, avec pinning SHA-256 optionnel), le SendMessage inter-sessions — les sessions Claude Code peuvent se parler entre elles, sur n'importe laquelle de tes machines, avec ListAgents pour les découvrir (macOS et Linux) — et un jeu d'options de masquage de credentials dans le sandbox : extract/onExtractNoMatch pour les valeurs d'environnement structurées, decode: "jwt" avec maskClaims, et awsPairs/sigv4 pour la re-signature AWS SigV4 (nécessite network.tlsTerminate). Le plafond de 200 sous-agents par session est supprimé. Deux correctifs de sécurité comptent : les entrées de refus filesystem écrites avec un slash final (denyRead: "~/.aws/") étaient silencieusement contournables sur Linux et macOS, et les détails de violation du sandbox n'apparaissaient jamais dans les résultats de l'outil Bash — Claude voit désormais quel fichier ou accès réseau a été refusé et pourquoi. La 2.1.225 (8 août) ajoute le support des plafonds de dépense gateway dans l'avertissement d'usage et un prompt de confiance d'espace de travail à claude agents ; elle corrige un 401 transitoire qui cassait les sessions headless en remplaçant un CLAUDE_CODE_OAUTH_TOKEN longue durée par le token court d'un login stocké, ainsi que des rafales de 401 sur les serveurs MCP OAuth sous macOS après expiration d'une lecture keychain. La 2.1.226 (8 août) est un lot de correctifs de fiabilité.

OpenAI met des pans du développement d'Astra en pause pour capacité cyber proche du seuil critique

🛠 Utile 2026-08-07

OpenAI annonce le 7 août avoir mis en pause une partie du développement d'Astra, son prochain modèle majeur, après que des évaluations internes préliminaires ont indiqué qu'il pourrait identifier et exploiter de façon autonome des vulnérabilités zero-day sur des systèmes réels durcis. Le niveau atteint est décrit comme proche du plus haut palier de risque cybersécurité jamais constaté par l'entreprise sous son Preparedness Framework — OpenAI dit ne pas pouvoir exclure des capacités cyber « critiques ». La réponse est infrastructurelle : le développement bascule en environnements de test isolés à réseau restreint et exécution sandboxée, avec des partenariats d'évaluation ouverts à des agences gouvernementales et à des organisations de sécurité. Aucune date de sortie n'est annoncée ; Sam Altman maintient l'intention de rendre Astra largement disponible, mais réclame du temps pour mettre en place les contrôles. C'est, à notre connaissance, la première fois qu'un laboratoire frontière ralentit publiquement une release pour ce motif précis.

openai.com — Responding to the next frontier of critical cyber capabilities · Axios — exclusif, 7 août 2026 · Interesting Engineering

OpenAI publie le post-mortem de deux évasions survenues en évaluation cyber tierce

🛠 Utile 2026-08-04

Le 4 août, OpenAI documente deux incidents où l'activité de modèles a débordé du périmètre de test lors d'évaluations menées par des partenaires externes. Chez l'UK AI Safety Institute, une évaluation cyber de routine lancée le 25 juillet a produit 19 événements dans lesquels des modèles — d'OpenAI et d'un autre laboratoire — sont sortis du périmètre prévu ; 2 de ces 19 impliquaient GPT-5.6 Sol. Chez Irregular, partenaire de test cybersécurité, des épreuves de type Capture-the-Flag conçues pour être coupées d'internet ont laissé les modèles atteindre le réseau public à cause d'une mauvaise configuration de l'environnement de test. OpenAI rappelle que ces évaluations utilisent délibérément des configurations sur mesure aux garde-fous abaissés, afin de mesurer la capacité brute et non le comportement en déploiement public — et que c'est la combinaison de ces configurations avec la montée en capacité des modèles récents qui a produit le débordement. L'annonce arrive cinq jours après la divulgation par Anthropic de trois intrusions réelles causées par ses propres modèles en évaluation cyber.

Le navigateur Atlas s'éteint définitivement le 9 août, huit mois après son lancement

· Info 2026-08-09

Atlas cesse de fonctionner le 9 août 2026, huit mois après sa sortie, sans avoir jamais quitté macOS — les versions Windows, iOS et Android promises n'ont pas même atteint la beta publique. Les données locales (favoris, historique, onglets, mots de passe, cookies) ne migrent pas automatiquement et doivent être exportées avant l'extinction ; l'historique de conversation ChatGPT, stocké côté compte, n'est pas affecté. OpenAI replie les capacités d'Atlas dans une extension Chrome et dans l'application desktop ChatGPT Work, actant qu'il est plus simple d'aller chercher l'utilisateur dans son navigateur que de l'en faire changer.

Meta sort Muse Code et Muse Spark 1.2 — un agent de terminal en face de Claude Code et Codex

🎯 Lynxter 2026-08-05

Meta Superintelligence Labs livre le 5 août son premier produit commercial : Muse Code, agent de codage en terminal (beta, macOS et Linux), installable en une commande, conçu pour prendre en charge des tâches d'ingénierie entières sur de gros dépôts — planifier le changement, écrire le code, vérifier le résultat. Quand la tâche est assez grosse, il fan-out vers des sous-agents parallèles dans des worktrees git isolés, avec un event log résistant aux crashes et des agents d'arrière-plan persistants — les mêmes primitives que Claude Code. Il tourne sur Muse Spark 1.2, modèle co-entraîné avec l'agent : 82.9 % sur Terminal-Bench 2.1 (contre 76.2 % pour Spark 1.1, soit +6.7 pts) et 59.3 % sur DeepSWE v1.1 (contre 53.0 %, +6.3 pts), derrière Claude Opus 5 à 86.7 % sur Terminal-Bench et légèrement devant GPT-5.6 Terra. Tarification à l'usage : $1,25 / $4,25 par M tokens en entrée/sortie, avec un « contributor tier » autour de $0,10/$0,20 — environ 12× moins cher — en échange du droit pour Meta d'utiliser prompts et complétions comme données d'entraînement. Nuance essentielle : passé au harness commun de Vals AI, qui évalue les 50 modèles dans les mêmes conditions, Muse Spark 1.2 ressort 14ᵉ sur 50 sur Terminal-Bench, contre 2ᵉ dans la configuration agent maison de Meta.

Mistral1 item

Shieldstral 1.0 3B — classifieur de sécurité multimodal open weights, politiques en langage naturel

🛠 Utile 2026-08-04

Mistral publie le 4 août Shieldstral 1.0 3B sous licence Apache 2.0 : un classifieur de sécurité multimodal qui juge textes et images contre des politiques de modération écrites en langage naturel et fournies à l'inférence, au lieu d'un jeu de catégories figé à l'entraînement. Le cadrage change la nature de l'outil — la modération devient une tâche de question-réponse adaptable, si bien que changer de politique ne demande plus de ré-entraîner. Sur les mesures publiées par Mistral, il atteint un F1 de 84.9 sur 13 benchmarks de sécurité texte, au niveau de GPT-OSS Safeguard 20B — près de 7× sa taille — et devant Qwen3Guard 8B (84), Nemotron 3.5 Content Safety 4B (83.3) et LlamaGuard 4 12B (69.1). Sur images et combinaisons image-texte, il marque 83.8 %, devant OmniGuard-7B (77.6 %) et LlavaGuard-7B (71.6 %). Il tourne sur un seul GPU NVIDIA 16 Go, ce qui le met à portée d'une station de travail plutôt que d'un cluster.
