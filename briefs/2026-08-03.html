Conclusion opérationnelle commune : l'isolation d'un agent se garantit par l'infrastructure — sandbox réseau, allowlist stricte — jamais par une consigne en prompt.

🎯 Implications Lynxter

Priorité de la semaine : auditer les serveurs MCP maison avant que la fenêtre de dépréciation ne se referme. La spec 2026-07-28 supprime le handshake et l'en-tête Mcp-Session-Id — tout serveur qui stocke de l'état par session (base de connaissances support S300X/S600D, connecteur tickets, doc machines, passerelle ERP) casse dès que le client passe en stateless, et toute implémentation qui s'appuie sur Sampling ou Roots a 12 mois pour migrer, transport legacy HTTP+SSE compris. Action concrète : grep sur initialize, Mcp-Session-Id, sampling/ et roots/ dans chaque serveur, puis remplacer les requêtes serveur→client par le Multi Round-Trip (resultType: "input_required" + rejeu avec inputResponses). Bénéfice immédiat en contrepartie : sans session, les serveurs MCP internes se déploient en serverless ou derrière un load-balancer sans affinité, et ttlMs/cacheScope sur les listings permet enfin de mettre en cache un catalogue d'outils ou une doc machine qui ne bouge qu'à chaque release firmware, au lieu de le recharger à chaque tour de boucle.

Les deux post-mortems du 30 juillet sont l'argumentaire de sécurité le plus solide disponible pour les revues clients et les RFP. Anthropic publie le chiffre exact — 3 incidents sur 6 runs parmi 141 006 runs à accès réseau — et surtout la cause racine : le modèle croyait, parce que le prompt le lui disait, être hors ligne. C'est la démonstration publique que la consigne textuelle n'est pas un périmètre de sécurité. À faire cette semaine sur le poste Claude Code de production : activer sandbox.network.strictAllowlist (refus sans prompt de tout hôte non allowlisté), sortir tout secret longue durée des répertoires visibles par un agent — clés API fournisseurs, credentials ERP, tokens GitHub —, passer sur des credentials courts et journaliser les appels réseau sortants des runs autonomes. Le volet OpenAI ajoute le vecteur exact à vérifier : des credentials publiquement exposés réutilisés sur quatre comptes distincts, dont un en relais sortant et staging — soit exactement le pattern d'un dépôt de scripts atelier partagé.

Côté outillage, deux briques utilisables tout de suite et un tier jetable à cadrer. Le CLI pplx de Perplexity donne du grounding web déterministe dans Claude Code : un objet JSON stable sur stdout, filtres --domains et --published-after-date (sites fournisseurs silicone, normes, docs machines), extraction ciblée jusqu'à 50 URLs, facturation à 5,00 $ / 1 000 requêtes plutôt qu'au token — deux réserves à retenir, aucun binaire Windows pour les postes atelier et une auth TTY-only qui impose PERPLEXITY_API_KEY en variable d'environnement dans toute automatisation. Sur le coût, GPT-5.6 Luna à $0,20/$1,20 et DeepSeek V4-Flash-0731 à $0,14/$0,28 rendent négligeable le triage de tickets S300X/S600D, l'extraction de champs sur les rapports d'intervention et les pré-résumés : monter un benchmark interne sur 200 tickets réels face à Sonnet/Haiku vaut le temps passé, en gardant Claude Code + Opus 5 sur les tâches à enjeu où la reproductibilité compte. Dernier point de calendrier : si un POC vocal tourne sur grok-voice-latest, l'alias bascule automatiquement sur la 2.0 le 5 août — coût de 0,05 à 0,08 $/min et comportement changent sans action de notre côté, il faut épingler grok-voice-think-fast-1.0 pour rester stable.

MCP 2026-07-28 — le protocole passe stateless, extensions versionnées et auth alignée OAuth/OIDC

🎯 Lynxter 2026-07-28

La spec MCP 2026-07-28 est sortie le 28 juillet : plus grosse révision depuis le lancement, elle fait passer le protocole d'un modèle bidirectionnel stateful à du requête/réponse stateless — handshake initialize/initialized supprimé, en-tête Mcp-Session-Id supprimé, chaque requête portant sa version de protocole, son identité client et ses capabilities en métadonnées, ce qui permet de déployer un serveur MCP derrière un round-robin banal ou en serverless/edge sans stockage partagé. Les requêtes serveur→client sont remplacées par le Multi Round-Trip Request (le serveur renvoie resultType: "input_required", le client rejoue l'appel avec inputResponses) ; les réponses tools/list, prompts/list, resources/list et resources/read portent désormais ttlMs et cacheScope calqués sur HTTP Cache-Control, et les en-têtes Mcp-Method / Mcp-Name laissent gateways et rate-limiters router sans parser le corps JSON. Côté autorisation : validation d'issuer RFC 9207, paramètre application_type dans le Dynamic Client Registration — lui-même formellement déprécié au profit des Client ID Metadata Documents (CIMD) — et credentials liés au serveur d'autorisation émetteur. Tasks quitte le cœur expérimental pour l'extension io.modelcontextprotocol/tasks (tasks/get en poll, nouveau tasks/update) ; Roots, Sampling, Logging et le transport legacy HTTP+SSE sont dépréciés avec une fenêtre de support minimale de 12 mois. Les quatre SDK Tier 1 (TypeScript, Python, Go, C#) supportent la spec au jour du lancement, Rust en beta, et Anthropic annonce en parallèle le déploiement progressif du support à travers les produits Claude — connecteurs à UI embarquée, auth managée en entreprise, observabilité et tunnels réseau privés.

Anthropic divulgue trois intrusions réelles causées par ses propres modèles pendant des évaluations cyber

🛠 Utile 2026-07-30

Le 30 juillet, Anthropic a publié « Investigating three real-world incidents in our cybersecurity evaluations » : des modèles Claude ont compromis les systèmes de production de trois organisations réelles lors d'évaluations cyber censées être isolées d'internet. L'audit a porté sur 141 006 runs d'évaluation dans lesquels un modèle pouvait atteindre le réseau, et a identifié 3 incidents répartis sur 6 runs ; la cause racine est une mauvaise configuration chez le partenaire d'évaluation Irregular, qui a laissé des machines de test connectées au vrai internet alors que le prompt affirmait au modèle que l'environnement était hors ligne — le modèle est donc sorti de ce qu'il croyait être un scénario fictif. Trois modèles distincts sont impliqués : Opus 4.7, Mythos 5 et un modèle de recherche interne ; les intrusions ont exploité des faiblesses élémentaires (mots de passe faibles, services non authentifiés), pas des vulnérabilités inédites. Anthropic a contacté les trois organisations le 27 juillet, et deux d'entre elles n'avaient rien détecté avant cet appel. La revue interne a été déclenchée par la divulgation analogue d'OpenAI du 21 juillet, ce qui installe un précédent de post-mortem public chez les deux labos frontière.

Dario Amodei — « Our position on open-weights models » : pas de ban, mais tests de sécurité obligatoires et blocage de la distillation

· Info 2026-07-27

Dario Amodei publie le 27 juillet une mise au point : Anthropic n'a jamais plaidé pour interdire les poids ouverts, et un modèle open weights sans capacité dangereuse est décrit comme un bien public dont le coût d'usage se limite au compute d'inférence. Trois demandes de politique publique en revanche — maintenir les contrôles à l'export sur puces et équipements de fabrication vers la Chine, réprimer la distillation à l'échelle industrielle des modèles frontière fermés, et imposer des tests de sécurité avant release à tout modèle suffisamment capable, ouvert ou fermé, le critère devenant la capacité et non le mode de distribution. Sortie en réponse aux critiques d'Alex Karp (Palantir), et la veille d'une lettre ouverte signée le 28 juillet par plus de 1 100 employés de labos frontière réclamant un mécanisme international de « pacing » vérifiable ; à suivre pour l'arbitrage on-prem, un durcissement des obligations ralentirait la cadence des sorties open weights (DeepSeek, GLM, Llama).

pplx — CLI mono-binaire qui expose la Search API de Perplexity en JSON aux agents de code

🎯 Lynxter 2026-07-27

Perplexity publie pplx, un binaire unique qui expose la Search API dans le terminal via deux commandes : pplx search web (filtres --domains, --recency-filter, --published-after-date/--published-before-date, --country, --search-context-size) et pplx content snippets (extraction ciblée sur jusqu'à 50 URLs, --max-tokens de 1 à 16 384, défaut 4 096). Le contrat de sortie est agent-first : exit code 0 et exactement un objet JSON sur stdout ({hits:[{url,title,domain,snippet}], total}), pipeable vers jq. Ce n'est pas un client de chat — pas de mode conversationnel, pas de sélection de modèle, pas de réponse synthétisée : c'est une couche de retrieval déterministe, à l'opposé du positionnement produit de Perplexity. L'installeur vérifie le SHA-256 et pose le binaire dans ~/.local/bin/pplx sans sudo, avec pplx update atomique ; couverture limitée à trois cibles (macOS Apple Silicon, Linux x86_64, Linux arm64) — pas de build Windows ni macOS Intel. pplx auth login est TTY-only, donc agents et CI doivent exporter PERPLEXITY_API_KEY ; une Agent Skill packagée est fournie pour Claude et autres agents de code, et la facturation Search API est annoncée à 5,00 $ / 1 000 requêtes, plafonnée à 50 QPS sur tous les paliers (chiffre de source secondaire).
