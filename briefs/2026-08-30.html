aux agents

TL;DR

  • Le 27 août, Anthropic ouvre le research preview du Model Hardware Standard. MHS est une spécification partagée pour que des agents opèrent des équipements physiques en sécurité : elle marche avec tout appareil doté d'une interface programmable, reste model-agnostic (n'importe quel harness y accède via des protocoles standards, MCP compris), rend les appareils découvrables, et laisse l'opérateur décrire en langage naturel ce qu'un manuel contient mais pas le code — masse d'un bras, limites de sécurité. L'intégration d'un instrument passe de plusieurs semaines à quelques heures ou minutes. Chiffres du preview : 58 % → 99,3 % de stabilisation laser chez QuEra, semaines → un jour sur une expérience d'imagerie chez HHMI Janelia, gestion d'erreurs en temps réel sur une expérience de drug discovery chez Genentech. Réservé pour l'instant à un groupe restreint d'organisations en science, robotique et manufacturing ; Anthropic annonce l'intention d'ouvrir le standard en open source.
  • Claude Code sort 2.1.248, 2.1.250 et 2.1.251 en deux jours, avec deux corrections de sécurité. La 2.1.251 corrige des outils fichiers qui suivaient les liens symboliques et pouvaient donc lire ou écrire hors des emplacements approuvés, ainsi que des commandes de plugin pointant hors du répertoire du plugin (traversée de chemin). La 2.1.248 ajoute un drapeau --restricted qui retire les outils intégrés (commandes, exécution de code, WebFetch), un experimental.cacheTtl par agent dans le frontmatter, et corrige un manque de cache de prompt survenant environ une fois par heure dans les sessions longues, causé par un re-rendu des définitions d'outils. La 2.1.251 ajoute les hooks PreModelSwitch / PostModelSwitch, une barre de plafond de dépense dans /usage et des métriques de cache par session dans /cost.
  • L'agent local devient un produit livrable, et OpenAI montre sa puce. Le même jour à Hot Chips, OpenAI publie les premiers chiffres de Jalapeño : 1,5 à 1,9× plus de travail par watt au débit maximal et 1,7 à 3,6× moins de latence bout-en-bout que les systèmes de comparaison, jusqu'à 2,1 à 4,1× sur les charges très interactives, mesurés sur GPT-OSS 120B, DeepSeek R1 et Kimi K2.5 1T.

🎯 Implications Lynxter

Le Model Hardware Standard vise explicitement le « manufacturing avancé » — c'est-à-dire vous. Depuis dix-huit mois, MCP a standardisé l'accès des agents aux outils logiciels ; MHS rejoue le même coup sur le matériel. La spécification s'applique à tout appareil doté d'une interface programmable, elle est model-agnostic (le harness importe peu, l'accès passe par des protocoles standards dont MCP), elle rend l'appareil découvrable, et surtout elle demande à l'opérateur d'écrire en langage naturel ce que le code ne contient pas : la masse du bras, l'enveloppe de sécurité, les limites à ne jamais franchir. Une S300X ou une S600D, avec son firmware, sa télémétrie et son interface de pilotage, entre exactement dans cette description. Ce qu'il faut faire cette semaine, avant même d'avoir accès au preview : inventorier la surface programmable de la machine (points d'entrée de contrôle, télémétrie disponible, ce qui est lisible et ce qui est écrivable), puis rédiger l'enveloppe de sécurité en français — températures maximales, états d'où l'on ne redémarre pas une impression, opérations qui exigent une présence humaine. Ce document est la moitié du travail d'intégration MHS le jour où le standard s'ouvre, et il n'a aucun coût d'option : il sert aussi de base à la documentation SAV.

Les deux correctifs de sécurité de Claude Code 2.1.251 rendent la mise à jour non négociable. Un outil fichier qui suit les liens symboliques peut lire ou écrire hors des emplacements approuvés — sur un poste de dev où le dépôt contient des liens vers des dossiers partagés, l'écart entre « l'agent travaille dans ce répertoire » et ce qu'il touche réellement n'est plus théorique. Même logique pour la traversée de chemin sur les commandes de plugin. Mettez à jour vers 2.1.251 et vérifiez la version sur les postes qui font tourner Claude Code sans surveillance. Dans la foulée, deux leviers concrets arrivent avec la 2.1.248 : --restricted retire les outils intégrés (commandes shell, exécution de code, WebFetch), ce qui donne enfin un profil serré pour un agent SAV qui doit lire de la doc et rédiger, jamais exécuter ; et experimental.cacheTtl permet de régler la durée de cache de prompt par agent, à combiner avec le correctif du manque de cache qui frappait environ une fois par heure les sessions longues. Sur un agent de support qui tourne la journée avec un gros prompt système, ce seul correctif se voit sur la facture.

Portable Computer prouve qu'un agent complet tient sur une machine d'atelier — et pose la bonne question de souveraineté. Perplexity fait tourner l'intégralité de la pile en local : orchestrateur, sous-agents, harness, sur un DGX Spark ou un simple x86 sous Ubuntu avec un GPU NVIDIA d'au moins 24 Go de VRAM, avec un PPLX 27B post-entraîné (Qwen 3.8 27B aussi disponible). Deux propriétés comptent pour Lynxter : le travail local ne consomme aucun crédit, et le système demande l'autorisation avant d'envoyer la moindre étape vers un modèle frontière dans le cloud. Traduction : un agent qui lit des plans clients, des fichiers de tranchage ou des rapports d'intervention sans qu'aucun de ces fichiers ne quitte le bâtiment par défaut — l'argument exact que réclament les RFP industriels et les clients aéronautique/médical. Comparez honnêtement : un 27B local ne joue pas dans la catégorie d'Opus 5 ou de GPT-5.6 sur du raisonnement long. Mais pour du tri de tickets, de la recherche dans la documentation machine et de la rédaction de réponses SAV, c'est largement suffisant, et le coût marginal par tâche tombe à zéro. Un test à 24 Go de VRAM coûte une carte, pas un contrat.

Model Hardware Standard — un standard pour que les agents pilotent des machines physiques

🎯 Lynxter 2026-08-27

Le 27 août, Anthropic ouvre la première phase du research preview du Model Hardware Standard (MHS), une spécification partagée pour que des agents IA découvrent, opèrent et dépannent des équipements physiques en recherche scientifique et en manufacturing avancé. Le principe : un pilote standardisé qui traduit entre le système d'exploitation et l'appareil avec des commandes simples de type lecture/écriture, de sorte qu'un agent n'ait plus besoin d'une intégration sur mesure par instrument — l'intégration passe de plusieurs semaines à quelques heures ou minutes. MHS fonctionne avec tout appareil doté d'une interface programmable, reste model-agnostic (n'importe quel harness d'agent y accède via des protocoles standards, MCP compris), rend les appareils découvrables, et demande à l'opérateur de décrire en langage naturel les caractéristiques que le code ne porte pas mais que le manuel contient : masse d'un bras robotisé, limites de sécurité. Les agents peuvent opérer plusieurs instruments en parallèle — microscopes, manipulateurs de liquides, bras robotisés. Trois résultats sont publiés avec le preview : stabilisation laser améliorée de 58 % à 99,3 % sur les calculateurs quantiques de QuEra, expérience d'imagerie comprimée de plusieurs semaines à une journée au HHMI Janelia Research Campus, et une expérience de drug discovery conduite avec gestion d'erreurs en temps réel chez Genentech. L'accès est limité à un groupe restreint d'organisations en science, robotique et manufacturing ; Anthropic déclare vouloir à terme ouvrir le standard en open source.

Claude Code 2.1.248 → 2.1.251 — deux évasions de chemin corrigées, un drapeau --restricted

🎯 Lynxter 2026-08-28

Trois versions en deux jours : 2.1.248 le 27 août, 2.1.250 et 2.1.251 le 28. Les deux correctifs qui comptent sont dans la 2.1.251 : les outils fichiers suivaient les liens symboliques et pouvaient donc lire ou écrire hors des emplacements approuvés, et des commandes de plugin pointaient hors du répertoire du plugin (erreur de traversée de chemin). Côté nouveautés, la 2.1.248 ajoute un drapeau --restricted qui retire les outils intégrés (commandes, exécution de code, WebFetch), un experimental.cacheTtl dans le frontmatter d'agent pour régler la durée de cache de prompt par agent, un claude self-hosted-runner --client-label, des diagnostics sur les réglages gérés côté serveur, et /usage-credits pour les organisations Enterprise sur AWS Marketplace ; elle corrige surtout un manque de cache de prompt survenant environ une fois par heure dans les sessions longues, causé par un re-rendu des définitions d'outils, et des sessions Claude Desktop et Cowork qui disparaissaient au bout de 30 jours. La 2.1.251 ajoute les hooks PreModelSwitch et PostModelSwitch, le streaming en direct des appels d'outils des sous-agents de premier plan vers les clients Remote Control, une barre de plafond de dépense dans /usage avec le champ rate_limits.spend_limit, des métriques de cache de prompt par session dans /cost, et les commandes attach, logs, stop, respawn, rm dans claude --help ; elle corrige des conversations bloquées sur « text content blocks must be non-empty » après un tour de pure réflexion, l'échec des requêtes Opus 5 en effort xhigh/max avec la réflexion désactivée, la lenteur du TUI avec beaucoup de sous-agents parallèles, et une réponse finale de coéquipier qui n'atteignait pas le chef d'équipe dans les agent teams.

Clés personnelles et clés de compte de service dans la Console, Admin API dans huit SDK

🛠 Utile 2026-08-27

Le 27 août, la Console Claude permet de créer des clés personnelles et des clés de compte de service. Elles agissent au nom de l'utilisateur ou du compte de service, avec exactement ses permissions, et cessent de fonctionner quand le compte lié quitte l'organisation — ce qui règle d'un coup le problème des clés orphelines. Elles peuvent être limitées à un espace de travail donné, ou couvrir les endpoints d'administration et tous les espaces auxquels le compte a accès ; les clés d'espace de travail restent supportées en option héritée. Le même jour, les SDK Python 1.2.0, TypeScript 0.122.0, Go 1.68.0, Java 2.59.0, Ruby 1.67.0 et C# 12.44.0 cessent d'envoyer les headers beta sur client.beta.files et client.beta.skills, qui renvoient désormais les mêmes formes que client.files et client.skills : client.beta.skills.delete() supprime maintenant une Skill avec toutes ses versions, et le type BetaSkill est renommé BetaContainerSkill. La veille, le 26 août, l'Admin API devient accessible depuis la CLI ant et huit SDK sous client.beta.organization.

Jalapeño — OpenAI publie les premiers benchmarks de sa puce d'inférence

🛠 Utile 2026-08-25

Le 25 août, à la conférence Hot Chips, OpenAI publie la première série de résultats de Jalapeño, sa puce d'inférence maison. Les chiffres, mesurés sur le benchmark InferenceX : au débit maximal, l'accélérateur délivre 1,5 à 1,9× plus de travail par watt que les systèmes commerciaux de comparaison, avec 1,7 à 3,6× moins de latence bout-en-bout, et jusqu'à 2,1 à 4,1× de gain sur les charges très interactives. L'argument central est de tenir les deux à la fois — débit et latence — là où les architectures existantes arbitrent généralement entre l'un et l'autre. Les mesures ont été prises sur GPT-OSS 120B, DeepSeek R1 et Kimi K2.5 1T, trois modèles ouverts, ce qui rend les chiffres au moins reproductibles en principe. Le déploiement commence avant fin 2026 dans l'infrastructure d'OpenAI, mais « en très petits volumes » selon l'entreprise, avec un vrai passage à l'échelle en 2027 ; une génération 2 est annoncée bien avancée et une génération 3 en conception. Le lendemain, 26 août, un billet de la directrice financière Sarah Friar replace la puce dans la pile complète — datacenters et puces, modèles frontière, plateforme développeur, produits, appareils.

Portable Computer — Perplexity fait tourner tout l'agent en local, sans crédit consommé

🎯 Lynxter 2026-08-25

Le 25 août, Perplexity lance Portable Computer, une version de sa plateforme agentique Computer dont toute la pile d'exécution — LLM orchestrateur, LLM sous-agent, harness d'agent — tourne sur le matériel de l'utilisateur, sans dépendance au cloud. Le modèle embarqué est un PPLX 27B post-entraîné et installé localement ; Qwen 3.8 27B est également disponible, et le support de NVIDIA Nemotron 3.5 Lightning est annoncé. Côté matériel, la première version cible les plateformes NVIDIA GB10 — DGX Spark, Dell Pro Max avec GB10 — ou tout PC x86 sous Ubuntu équipé d'un GPU NVIDIA d'au moins 24 Go de VRAM. Deux propriétés font la différence : le travail effectué localement ne consomme aucun crédit de facturation, et chaque tâche démarre sur l'appareil par défaut, le système demandant une autorisation explicite avant d'envoyer la moindre étape vers un modèle frontière dans le cloud. L'accès est réservé aux abonnés Pro et Max, sur Linux d'abord, Windows annoncé. En parallèle, Personal Computer arrive sur Mac dans l'application de bureau, avec édition de fichiers locaux, contrôle de la machine, navigation locale via Comet et orchestration vocale.

Cursor détache ses cloud agents de tout fournisseur SCM

🛠 Utile 2026-08-27

Le 27 août, les cloud agents de Cursor cessent d'exiger un GitHub — ou tout autre fournisseur SCM — connecté pour démarrer. On peut désormais lancer un prompt immédiatement, puis sauvegarder le travail dans un dépôt Cursor Origin en choisissant « Start from scratch » dans le sélecteur de dépôt. Deux ajouts complètent la boucle : Cursor redirige le port de l'environnement vivant du cloud agent directement vers le navigateur, ce qui permet de prévisualiser ce que l'agent construit pendant qu'il le construit, et un compte Vercel connecté permet de publier en un clic pour obtenir une URL en ligne. C'est la suite directe de Cursor Origin, l'hébergement de code lancé en beta le 17 août, et des améliorations de harness du 19 août qui visaient des agents capables de tenir un objectif sans intervention à chaque boucle.
