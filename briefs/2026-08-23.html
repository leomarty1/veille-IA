TL;DR

  • Le 19 août, Anthropic sort cinq briques du beta et lance le browser use tool. Computer use devient computer_toolset_20260801 sans header beta, avec actions en batch (plusieurs actions par tour) et zoom activé par défaut ; le nouveau browser_toolset_20260801 travaille dans un viewport que l'application héberge, lit l'arbre d'accessibilité de la page et ajoute références d'éléments, saisie de formulaires, gestion d'onglets et upload de fichiers en opt-in. Files API, Agent Skills, Skills API (/v1/skills) et les endpoints user-management de l'Admin API perdent aussi leurs headers beta. Les deux toolsets tournent sur Fable 5, Mythos 5, Opus 5, Sonnet 5 et Opus 4.8.
  • Claude Code sort huit versions en sept jours (2.1.234 → 2.1.241). Deux correctifs pèsent en production : le streaming Bedrock derrière un proxy qui supprime le header Content-Type doublait silencieusement les appels API facturés en rejouant chaque tour en non-streaming, et la croissance mémoire non bornée des sessions longues est corrigée (les résultats d'outils des sous-agents sont libérés une fois hors fenêtre d'affichage). Côté nouveautés : style de sortie Concise, variable ANTHROPIC_DEFAULT_MODEL, keybindingFlavor: "readline", notify_when_idle sur SendMessage, badge merge request GitLab, et /claude-api upgrade pour migrer les projets Python vers le SDK 1.x.
  • SDK Python v1.0 le 20 août : migration obligatoire, pas un simple bump. La couche HTTP passe de httpx à httpx2, Python 3.10 devient le minimum, et la surface dépréciée disparaît — API Text Completions legacy, paramètres temperature, top_p et top_k sur les méthodes Messages, compaction_control côté client du tool runner. Sur le client async, .with_raw_response exige désormais await response.parse(), et AnthropicBedrock lève une erreur au lieu de retomber sur us-east-1 quand aucune région AWS n'est configurée.

🎯 Implications Lynxter

Le browser use tool est la brique qui manquait pour automatiser les portails fournisseurs. Depuis un an, l'automation des vieux outils métier passait par computer use — l'agent voit un bureau entier, prend des captures, clique à l'aveugle sur des coordonnées. Le browser_toolset_20260801 change la nature du contrôle : il travaille dans un viewport que ton application héberge, lit l'arbre d'accessibilité de la page (éléments, formulaires, onglets) et manipule des références d'éléments plutôt que des pixels — plus la gestion des onglets, le report des téléchargements et l'upload de fichiers en opt-in. Concrètement pour Lynxter : les portails de commande filaments, les extranets de transporteurs, les back-offices SAV sans API deviennent scriptables avec une fiabilité qui ne dépend plus du rendu graphique ni de la résolution d'écran. À faire cette semaine : prends le workflow le plus pénible de la liste (relevé hebdomadaire des délais fournisseurs, dépôt de dossier de garantie), monte un prototype sur browser_toolset_20260801 et mesure le taux de réussite sur 20 itérations. Ne pars pas de computer use pour ce cas d'usage : le browser tool est plus étroit, donc plus prévisible, et c'est exactement ce que tu veux sur un process qui touche des commandes.

Agent Skills en GA transforme les Skills d'expérimentation en dépendance assumée. Le retrait du header skills-2025-10-02 n'est pas cosmétique : une capacité en beta chez Anthropic peut changer de forme de requête sans préavis, une capacité GA non. Tes Skills maison — procédure de diagnostic S300X, arbre de décision extrusion, gabarit de réponse SAV — peuvent maintenant être adossées à la /v1/skills API et chargées via le paramètre container des requêtes Messages sans header spécial, ce qui les rend versionnables et testables comme du code. Deux compléments du 19 août rendent l'ensemble déployable en production : les agents Managed Agents acceptent désormais allowed_domains et blocked_domains sur web_search et web_fetch, et les sessions en sandbox auto-hébergée peuvent attacher des memory stores synchronisés dans les deux sens à leur mount_path. Ça répond à la question qui bloquait le déploiement d'un agent SAV chez un client industriel : garantir que l'agent ne sorte pas d'une liste blanche de domaines, et garder sa mémoire de travail sur une infrastructure que le client contrôle. Chiffrage à faire : liste les cinq domaines que ton agent support a le droit d'atteindre et écris la config configs correspondante — c'est vingt lignes, et c'est ce qui transforme un POC en argumentaire RFP.

Les deux correctifs Claude Code de la semaine valent un audit de facture. Le bug Bedrock corrigé en 2.1.239 est le genre de défaut qu'on ne voit pas : derrière un proxy qui supprime le header Content-Type de la réponse, le streaming échouait et Claude Code rejouait chaque tour en non-streaming — soit deux appels API facturés pour un seul tour de conversation, sans message d'erreur. Si une partie de ton usage passe par Bedrock derrière un proxy d'entreprise, compare le nombre d'appels facturés au nombre de tours réels sur juillet et août avant de conclure. Le second correctif, la croissance mémoire non bornée des sessions interactives longues (2.1.238), concerne directement les routines qui tournent des heures avec des sous-agents : leurs résultats d'outils restaient en mémoire indéfiniment. En pratique, épingle une version : ANTHROPIC_DEFAULT_MODEL arrivé en 2.1.236 permet de fixer le modèle de démarrage des nouvelles sessions sans figer le choix /model — utile pour homogénéiser un poste d'astreinte SAV sans imposer le modèle à qui veut monter en xhigh sur un audit firmware. Et si tu maintiens du Python contre l'API Claude, lance /claude-api upgrade (2.1.239) avant que le SDK 0.x ne dérive : la v1.0 sortie la veille casse assez de surface pour qu'une migration manuelle coûte une demi-journée.

Computer use, Files API, Agent Skills et Admin API sortent du beta — et le browser use tool arrive

🎯 Lynxter 2026-08-19

Le 19 août, cinq briques de la plateforme Claude quittent le beta le même jour. Computer use devient le toolset computer_toolset_20260801 : plus de header beta, actions en batch (plusieurs actions dans un seul tour), zoom activé par défaut et configuration par membre via configs — la mise à niveau change la forme de requête, ce n'est pas un renommage. Anthropic lance en parallèle le browser use tool (browser_toolset_20260801), un toolset client qui pilote un navigateur hébergé par l'application : il travaille dans un viewport plutôt que sur un bureau entier, lit la page elle-même (arbre d'accessibilité, éléments, formulaires, onglets) et ajoute références d'éléments, saisie de formulaires, gestion d'onglets, report de téléchargements et upload de fichiers en opt-in par-dessus le contrôle capture-et-clic. Les deux toolsets sont disponibles sur Fable 5, Mythos 5, Opus 5, Sonnet 5 et Opus 4.8. La Files API perd le header files-api-2025-04-14 et adopte l'expiration de fichiers (expires_in_seconds, expires_at) plus la pagination page/next_page avec filtre ids[]. Agent Skills et la Skills API (/v1/skills) perdent skills-2025-10-02, y compris pour les requêtes Messages qui chargent des Skills via container. Les endpoints user-management de l'Admin API pour les organisations Claude Enterprise (membres, invitations, groupes, rôles personnalisés) sortent aussi du beta.

Claude Code 2.1.234 → 2.1.241 — huit versions, un bug de double facturation Bedrock, une fuite mémoire

🎯 Lynxter 2026-08-23

Huit versions en sept jours, du 17 au 23 août. Deux correctifs comptent en production. La 2.1.239 répare le streaming Bedrock derrière un proxy qui supprime le header Content-Type de la réponse : le tour repartait en non-streaming, ce qui doublait silencieusement les appels API facturés. La 2.1.238 corrige une croissance mémoire non bornée dans les sessions interactives longues — les résultats d'outils des sous-agents sont désormais libérés dès qu'ils quittent la fenêtre d'affichage récente. Côté nouveautés : style de sortie intégré Concise (2.1.237), variable ANTHROPIC_DEFAULT_MODEL qui fixe le modèle de démarrage des nouvelles sessions sans écraser un choix /model (2.1.236), notify_when_idle sur SendMessage pour être prévenu une seule fois quand une autre session passe en idle (2.1.236), réglage keybindingFlavor: "readline" (2.1.238), headersHelper sur les marketplaces de plugins pour générer des en-têtes HTTP éphémères (2.1.238), options --defer-shutdown-max-min et --proxy-authorization-command sur le self-hosted runner (2.1.238), badge merge request GitLab dans le footer et la statusline (2.1.234), continuation automatique de session à la remise à zéro du quota claude.ai (2.1.234), et /claude-api upgrade pour migrer un projet Python de anthropic 0.x vers 1.x (2.1.239). Le mode auto gagne en rigueur : les règles d'autorisation Monitor sont mises de côté quand il est actif, et le contrôle de propreté du dépôt ne se laisse plus tromper par status.showUntrackedFiles=no (2.1.236). Sur macOS, les règles sandbox de refus de lecture à joker (par exemple **/.env) priment désormais à l'intérieur des zones autorisées et ne peuvent plus être contournées en renommant le fichier (2.1.236).

Managed Agents — listes blanches de domaines, memory stores en sandbox auto-hébergée, session viewer redessiné

🛠 Utile 2026-08-19

Trois changements le 19 août sur Claude Managed Agents. On peut désormais restreindre les sites que les outils web_search et web_fetch d'un agent peuvent atteindre : allowed_domains ou blocked_domains se posent sur l'entrée de l'outil dans le tableau configs du toolset agent_toolset_20260401, web_fetch acceptant en plus max_content_tokens et web_search un user_location. Chaque entrée configs est identifiée par son name et typée par un type facultatif ; les requêtes qui ne passent que name, enabled et permission_policy continuent de fonctionner. Deuxième changement : les sessions qui tournent dans une sandbox auto-hébergée peuvent attacher des memory stores — les workers des SDK Python, TypeScript et Go téléchargent chaque store attaché dans la sandbox à son mount_path et resynchronisent les modifications de l'agent vers le store. Troisième : le session viewer de la Console est redessiné, avec minimap chronologique, transcription groupée par requête modèle et panneau Inspector (détails et coût de session, événements bruts, statistiques par outil, ressources montées, activité par thread).

SDK Python v1.0 — passage à httpx2, Python 3.10 minimum, suppressions cassantes

🛠 Utile 2026-08-20

Le 20 août, le SDK Python d'Anthropic passe en v1.0. La couche HTTP quitte httpx pour httpx2, un fork maintenu et compatible API : les objets http_client, Timeout et transports personnalisés se construisent désormais depuis httpx2 (les helpers DefaultHttpxClient ne changent pas), et il faut appeler httpx2.alias_httpx() au démarrage si une bibliothèque de tracing ou de mock patche httpx. La v1.0 exige Python 3.10 ou supérieur et supprime la surface dépréciée de longue date : API Text Completions legacy, paramètres temperature, top_p et top_k sur les méthodes Messages, et compaction_control côté client du tool runner. Sur le client asynchrone, les résultats de .with_raw_response exigent maintenant await response.parse(), et AnthropicBedrock lève une erreur quand aucune région AWS n'est configurée au lieu de retomber sur us-east-1. Le guide de migration v1 liste chaque changement avec des extraits avant/après — et Claude Code a ajouté dès le lendemain une commande /claude-api upgrade qui fait la migration 0.x → 1.x sur un projet Python.

platform.claude.com — release notes (20 août 2026) · anthropic-sdk-python — guide de migration v1

Roadmap MCP du 22 août — cinq chantiers, dont les tâches longues et l'identité d'agent

🎯 Lynxter 2026-08-22

Les Core Maintainers de MCP publient le 22 août une roadmap pour la prochaine version de spécification et au-delà, élaborée avec la communauté des mainteneurs et les Working Groups. Cinq chantiers prioritaires : primitives de messagerie agentique (patterns de tâches longues via événements initiés par le serveur, composition de tâches, maturation de l'extension Tasks) ; unification du transport HTTP (standardisation sur des transports HTTP en local comme en distant, y compris Streamable HTTP par-dessus stdio) ; identité d'agent et sécurité entreprise (identité d'agent standardisée avec DPoP — Demonstrating Proof of Possession — et Workload Identity Federation) ; primitives améliorées (contrats de traitement des résultats d'outils, découverte progressive pour les catalogues d'outils volumineux) ; ergonomie des SDK (conformité à la spécification et documentation). Aucune date de release n'est donnée pour la prochaine version au-delà de la référence à l'actuelle 2026-07-28 — celle qui a rendu le cœur du protocole sans état en supprimant le handshake initialize/initialized et l'en-tête Mcp-Session-Id. Ordre de grandeur d'adoption cité par le projet : les SDK Tier 1 approchent le demi-milliard de téléchargements par mois, TypeScript et Python ayant franchi le milliard cumulé.

OpenAI met à jour son Model Spec — principes U18 et section sur les limites de capacité

🛠 Utile 2026-08-18

Le 18 août, OpenAI met à jour son Model Spec, le document vivant qui décrit le comportement attendu de ses modèles. L'ajout principal est un ensemble de principes U18 qui s'empile sur les règles de sécurité applicables à tous les utilisateurs et précise leur application aux conversations avec des adolescents de 13 à 17 ans : pas de jeu de rôle romantique immersif ni d'intimité à la première personne, refus des mises en scène violentes ou sexualisées même non graphiques, refus des activités dangereuses, du mésusage de substances et de toute tentative de dissimuler un préjudice, prudence accrue sur l'image du corps et les comportements alimentaires. Deux modifications intéressent directement la conception de prompts : une nouvelle section « Be clear about capabilities and limits », et une clarification de la façon dont l'assistant doit traiter les prémisses fausses ou non étayées — le point de friction classique quand un utilisateur affirme un fait erroné dans sa question. La mise à jour retire par ailleurs les consignes devenues obsolètes qui visaient les modèles antérieurs au raisonnement.

ChatGPT for Teens — expérience dédiée aux 13-17 ans

· Info 2026-08-18

OpenAI lance le 18 août ChatGPT for Teens : toute personne que le système estime mineure, ou qui déclare avoir entre 13 et 17 ans, bascule automatiquement dans cette expérience. Elle ajoute des restrictions de contenu autour du suicide, de l'automutilation et des échanges romantiques ou sexuels, des contrôles parentaux, un Study Mode qui pousse des questions guidées et un accompagnement pas à pas plutôt que la réponse directe, et des rappels de devoirs qui apparaissent quand l'usage ressemble à de la triche. Le lancement accompagne la mise à jour du Model Spec publiée le même jour.

Équipe Preparedness — dissolution rapportée par le Financial Times, contestée par OpenAI

· Info 2026-08-17

Plusieurs médias reprennent à partir du 17 août une information du Financial Times selon laquelle OpenAI aurait dissous fin juillet son équipe Preparedness, chargée d'évaluer si ses modèles peuvent présenter des risques graves voire catastrophiques, en réaffectant ses membres seniors aux équipes cyber et bio existantes — sans licenciement. Sans annonce officielle : OpenAI conteste la dissolution et affirme que l'équipe existe toujours, et l'entreprise n'a publié aucun communiqué sur le sujet. À suivre comme signal de gouvernance plutôt que comme fait établi, dans un contexte de départs de dirigeants et de préparation d'introduction en bourse.

Google éteint les endpoints Imagen 4 — la migration n'est pas un renommage

· Info 2026-08-17

Les trois modèles imagen-4.0-generate-001, imagen-4.0-ultra-generate-001 et imagen-4.0-fast-generate-001 atteignent le 17 août leur date d'extinction sur l'API Gemini, Google recommandant la bascule vers la famille Gemini 3.x Image et en particulier gemini-3.1-flash-image. Le remplacement change la forme d'appel et pas seulement le nom du modèle : Imagen utilisait generate_images et renvoyait une réponse image dédiée, la nouvelle famille passe par generate_content et renvoie des parties de contenu susceptibles de porter des données image. Prochaine échéance sur le même calendrier : l'extinction des modèles Gemini 2.5 en octobre 2026.

Cursor ouvre Origin, son hébergement de code, puis muscle ses cloud agents

🛠 Utile 2026-08-19

Deux livraisons en trois jours. Le 17 août, Cursor ouvre Origin en beta anticipée sur tous les plans payants (Pro, Teams, Enterprise) : hébergement de code intégré à l'éditeur, avec dépôts, pull requests, navigation de code et synchronisation GitHub, accessible par un onglet du client desktop et par un outil en ligne de commande dédié ; les fonctionnalités pensées pour les agents sont annoncées pour plus tard, et le changelog de Cursor maintient GitHub comme source de vérité.
