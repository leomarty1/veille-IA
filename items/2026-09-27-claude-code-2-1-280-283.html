Contexte étendu

La séquence 2.1.280 → 283 couvre quatre jours, du 22 au 25 septembre, et se lit en deux blocs : la sûreté du mode auto d'un côté, la gouvernance d'entreprise de l'autre. 2.1.280 (22 septembre) fait d'Opus 5.5 le modèle Opus par défaut du CLI et corrige trois comportements du mode auto. Le plus sérieux concerne les liens symboliques : une écriture dont le chemin traversait un symlink était évaluée sur son orthographe dans l'arbre de travail plutôt que sur sa destination, de sorte que acceptEdits, les règles d'autorisation et le mode auto pouvaient approuver une écriture atterrissant en dehors du répertoire de travail ; le prompt nomme maintenant l'endroit où l'écriture atterrit réellement. Les deux autres corrigent des boucles : une action qu'un contrôle de sûreté refuse d'examiner est désormais refusée une seule fois avec la mention que réessayer ne servira à rien, et quand le contrôle ne répond pas, les tentatives ralentissent puis le tour s'arrête après dix refus consécutifs. La version ajoute aussi CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH pour déplacer le plafond de 2 048 caractères sur les descriptions d'outils MCP.

2.1.281 (23 septembre) est la version entreprise : sur la passerelle Claude apps, les upstreams Bedrock acceptent un assume_role via STS — y compris vers un autre compte AWS et avec une session par développeur — et un guardrail: {id, version} appliqué à toutes les requêtes. Elle ajoute telemetry.resource_attributes pour étiqueter la télémétrie, l'élicitation MCP en mode URL sur les connexions au protocole 2026-07-28, des vérifications MCP dans claude plugin validate (entrées .mcp.json silencieusement ignorées, références ${user_config.*} non déclarées, URL non sécurisées), et une recommandation de mode auto dans /insights qui estime combien de demandes d'autorisation il aurait pu absorber. Le réglage "attribution": false dans settings.json masque toute attribution sur les commits et les PR. 2.1.282 (24 septembre) ajoute maxProseWidth et corrige une série de pertes de raisonnement sur sessions reprises ou continuées, ainsi que l'échec de compaction quand la requête de résumé est refusée — elle repart maintenant sur un modèle de repli.

2.1.283 (25 septembre) apporte les deux nouveautés les plus directement exploitables. /doctor prompt-audit (aussi /checkup prompt-audit) relit les fichiers CLAUDE.md, les skills, les agents et les commandes d'un dépôt pour signaler les tournures de prompt écrites pour des modèles plus anciens. Côté gouvernance, deniedModels bloque des modèles nommément même quand availableModels les autorise, et availableModelsMatch: "exact" fait qu'une entrée d'availableModels n'autorise que la version exacte nommée — les nouvelles sorties restent bloquées tant qu'elles ne sont pas listées. S'y ajoutent x-claude-code-prompt-id pour regrouper côté passerelle les requêtes servant un même prompt, et les sorties d'outils MCP, WebFetch et WebSearch dans l'événement OpenTelemetry tool.output sous OTEL_LOG_TOOL_CONTENT=1.

Face à la concurrence, la semaine est symétrique mais pas équivalente. Codex CLI a ajouté GPT-6 Sol et Luna au sélecteur de modèles avec support Bedrock et passé les transcriptions en plein écran par défaut ; Cursor a livré deux bots CI (Rollouts et Security Review). Aucun des deux n'expose d'équivalent à /doctor prompt-audit ni à la paire deniedModels / availableModelsMatch : sur la gouvernance fine des modèles autorisés dans une organisation, Claude Code prend une avance nette cette semaine, là où Cursor investit plutôt la chaîne de livraison.

🎯 Pourquoi c'est important pour Lynxter

Le correctif symlink se traite comme un correctif de sécurité, avec une date. La question à se poser est concrète : existe-t-il, sur les postes ou les runners où Claude Code tourne en mode auto ou avec acceptEdits, des liens symboliques pointant vers des dossiers partagés, des montages réseau ou la racine d'un autre dépôt ? Si oui, toute version antérieure à 2.1.280 pouvait approuver une écriture atterrissant hors du répertoire de travail sans que le prompt le signale. Action : vérifie la version installée sur chaque poste et chaque runner, et impose 2.1.280 au minimum — c'est un correctif, pas une option de confort.

Passe /doctor prompt-audit sur le dépôt de veille et sur les skills de support. Le CLAUDE.md de la veille accumule des consignes depuis des mois, écrites pour des modèles successifs, et le passage à Opus 5.5 change la donne : la pensée est permanente et se règle par effort, donc toutes les tournures qui demandaient au modèle de « réfléchir étape par étape » ou de simuler un raisonnement sont au mieux inutiles. Action : lance /doctor prompt-audit sur ce dépôt et sur les skills de support, et traite ce qu'il remonte comme une liste de dette à purger, pas comme un avis.

deniedModels et availableModelsMatch donnent enfin de quoi figer les modèles d'un poste de support. Jusqu'ici, autoriser une famille de modèles laissait passer les nouvelles versions dès leur sortie — pratique en veille, problématique sur un poste où les réponses client doivent rester reproductibles d'une semaine sur l'autre. Avec availableModelsMatch: "exact", une nouvelle version reste bloquée tant qu'elle n'est pas explicitement listée, et deniedModels permet d'exclure un modèle précis. Action : si un poste de support tourne sur une configuration validée, passe-le en mode exact et fais de l'ajout d'un modèle une décision datée plutôt qu'un effet de bord.

Réserve. "attribution": false est tentant pour des commits internes, mais le changelog précise que les versions plus anciennes du CLI ignorent entièrement un fichier de réglages qui le contient — à ne poser que sous forme d'objet dans un fichier partagé entre versions, sous peine de désactiver silencieusement tous les autres réglages du fichier sur les postes en retard.
