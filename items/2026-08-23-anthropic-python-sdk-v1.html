SDK Python v1.0 — passage à httpx2, Python 3.10 minimum, suppressions cassantes

Contexte étendu

Le changement structurant est le déplacement de la couche HTTP de httpx vers httpx2, présenté comme un fork maintenu et compatible au niveau API. En pratique, le code qui construit un http_client, un Timeout ou un transport personnalisé doit importer ces objets depuis httpx2 — les helpers DefaultHttpxClient, eux, ne changent pas. Le piège n'est pas dans le code applicatif mais dans l'outillage autour : toute bibliothèque de tracing, de mock ou d'enregistrement de requêtes qui patche httpx cesse de voir les appels. La parade documentée est un appel à httpx2.alias_httpx() au démarrage du processus. Une suite de tests qui repose sur un enregistrement HTTP passera donc de verte à silencieusement vide sans cette ligne — c'est le mode de rupture le plus probable dans une CI existante.

Les suppressions sont assumées et de nature différente les unes des autres. L'API Text Completions legacy disparaît : elle était dépréciée depuis longtemps, son retrait ne concerne plus que du code très ancien. Les paramètres temperature, top_p et top_k sur les méthodes Messages disparaissent aussi — cohérent avec le comportement des modèles récents, où Sonnet 5 renvoie déjà une erreur 400 quand ces paramètres sont mis à une valeur non par défaut et où le pilotage passe par effort. Le compaction_control côté client du tool runner s'en va également. S'ajoutent deux changements de comportement à fort potentiel de surprise : sur le client asynchrone, les résultats de .with_raw_response exigent désormais await response.parse(), et AnthropicBedrock lève une erreur quand aucune région AWS n'est configurée au lieu de retomber silencieusement sur us-east-1. Ce dernier point est une amélioration déguisée en rupture : une intégration qui marchait « par hasard » sur la mauvaise région le dira désormais.

Le calendrier interne d'Anthropic mérite d'être noté : le SDK passe en v1.0 le 20 août, et Claude Code livre /claude-api upgrade dès le 21 (version 2.1.239) pour migrer un projet Python de anthropic 0.x vers 1.x, avec la référence Python de la skill mise à jour pour la 1.x — les timeouts s'y construisent désormais avec anthropic.Timeout et non httpx.Timeout. La même version réduit par ailleurs le coût en contexte de la skill claude-api intégrée d'environ 200 000 tokens à environ 25 000, en chargeant la documentation de référence à la demande. Autrement dit : la migration est outillée le lendemain de la rupture, et l'outil qui la fait coûte huit fois moins de contexte qu'avant.

🛠 Pourquoi c'est utile à savoir pour Lynxter

Si tu as du Python qui appelle l'API Claude, planifie la migration maintenant plutôt qu'en urgence. Les scripts d'automatisation qui tournent contre l'API — extraction de données de tickets, génération de rapports, classification de logs machine — utilisent presque tous le SDK. Action concrète : lance /claude-api upgrade depuis Claude Code sur le dépôt concerné, puis relis le diff sur trois points précis — les imports httpx devenus httpx2, les éventuels temperature passés aux méthodes Messages (à supprimer, pas à déplacer), et la configuration de région si tu passes par Bedrock.

Le risque réel n'est pas le code applicatif, c'est la CI. Si tes tests mockent ou enregistrent les appels HTTP via une bibliothèque qui patche httpx, ils continueront de passer tout en n'observant plus rien — le pire mode d'échec possible pour une suite de tests. Action concrète : avant de merger la migration, ajoute httpx2.alias_httpx() au démarrage de la configuration de tests, puis vérifie par un test volontairement cassé que la suite échoue bien. Une suite qui reste verte sur un test qui devrait échouer est le signal que le patch ne voit plus les requêtes.

La suppression de temperature confirme une bascule de méthode. Sur les modèles récents, le pilotage ne passe plus par l'échantillonnage mais par effort — low à max. Si des prompts internes règlent encore la température pour « rendre les réponses plus déterministes » sur des tâches de classification support, ce réglage n'a plus d'effet et disparaît de la surface. Action concrète : identifie ces appels, remplace l'intention par un niveau d'effort explicite et un format de sortie contraint (schéma JSON), et re-mesure la stabilité sur un échantillon de vingt tickets. C'est plus fiable que la température ne l'a jamais été, et c'est désormais la seule voie disponible.
