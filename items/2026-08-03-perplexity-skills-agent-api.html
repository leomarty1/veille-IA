Contexte étendu

Le mécanisme de Skills introduit dans l'Agent API reprend le patron des Agent Skills d'Anthropic, sans détour : un tableau skills accepte à la fois des entrées built-in issues d'un catalogue (par exemple office/pdf) et des skills inline définies pour la requête en cours. Le point d'ingénierie est le chargement paresseux : le modèle ne voit d'abord que le nom et la description de chaque skill, et n'en charge les instructions complètes qu'au moment où il décide d'en avoir besoin. Conséquence directe sur la facture, le contexte d'une skill n'est payé que si elle est effectivement utilisée — ce qui rend viable d'en exposer une dizaine sans faire exploser le prompt système. Un Skills Directory étendu est annoncé comme à venir.

Le reste du lot côté produit est plus classique mais pas anodin : Claude Opus 5 est disponible dans Search et dans Computer, Computer devient accessible depuis Comet Assistant, s'ajoutent des credentials API personnalisés, l'extension de la mémoire Brain à davantage de langues, Check Sources, un Source Context Panel et de nouveaux outils de gestion de sessions. Le fait qu'Opus 5 soit consommable via Perplexity est le point le plus structurant : il découple l'accès au modèle du contrat fournisseur.

Côté Enterprise, Perplexity comble un retard d'administration : rôles personnalisés à permissions granulaires, synchronisation de groupes depuis l'IdP via SCIM, et plafonds de consommation de crédits par groupe — le tout réservé aux organisations sous contrat annuel, avec des allocations mensuelles de référence de 500 crédits en Enterprise Pro et 15 000 en Enterprise Max. Note de sourcing : aucune source primaire n'a pu être fetchée, tous les hôtes perplexity.ai (hub, changelog, docs, help-center, forum) renvoyant 403 via le proxy d'egress.

🛠 Pourquoi c'est utile à savoir pour Lynxter

Le modèle Skills rend transférable ce qui est déjà écrit pour Claude Code. Une skill « doc technique Lynxter » ou « format rapport d'intervention » — c'est-à-dire un bloc d'instructions et de conventions maison — peut être exposée à un agent Perplexity via le tableau skills sans réécriture d'architecture. C'est la deuxième convergence de la semaine après MCP : les briques d'outillage agent (protocole de connexion d'un côté, instructions conditionnelles de l'autre) se standardisent de fait autour des formats Anthropic, ce qui réduit le risque d'enfermement quand on écrit du contenu d'agent aujourd'hui.

Opus 5 accessible via Perplexity change l'arbitrage fournisseur, pas la stack. Pouvoir consommer Opus 5 sans contrat Anthropic distinct est un argument commercial pour qui veut un socle unique — mais pour Lynxter, dont le poste de travail agent est déjà Claude Code, ça n'a d'intérêt que comme point de comparaison de coût : facturation en crédits Perplexity contre facturation au token Anthropic, sur un volume mensuel réel. À vérifier avant toute conclusion, un modèle en crédits masque le prix marginal.

Le volet SCIM et plafonds par groupe est le vrai signal Enterprise. Provisioning depuis l'IdP et plafond de consommation par groupe, c'est l'outillage qu'on demandera nous-mêmes le jour où plusieurs postes support consomment des agents — savoir qui a accès à quoi et couper le robinet avant la surprise de facturation. À noter comme critère d'évaluation pour toute plateforme d'agents qu'on considérerait, Perplexity ou autre : sans rôles granulaires ni plafonds par groupe, un déploiement multi-postes n'est pas administrable.
