Contexte étendu

Perplexity publie le 28 septembre la première partie d'un red team d'un mois sur SPACE, le runtime Firecracker microVM qui exécute le code de Perplexity Computer, mené avec NVIDIA via le Secure Intelligence Institute. Neuf modèles — dont Claude Opus 5, GPT-5.6 Sol, Kimi K3 et Gemini 3.1 Pro — recevaient un accès root et parfois le code source du sandbox, avec pour objectif de s'évader vers l'hôte ou de joindre une URL bloquée. Aucun n'a franchi la frontière VM sur 108 runs.

La politique réseau a en revanche cédé : 4 modèles l'ont contournée par spoofing DNS ou en passant par des IP de CDN partagées — l'un a fait transiter une requête par le fetcher d'images de Taboola puis lu le résultat par OCR d'une capture. Perplexity a corrigé ces failles. Testées avec la même technique, 8 plateformes sandbox tierces sur 10 étaient vulnérables au contournement par IP partagée, E2B, Vercel et Modal étant cités. La leçon technique : un filtrage par adresse IP ne tient pas face à des services mutualisés derrière les mêmes CDN.

🛠 Pourquoi c'est utile à savoir pour Lynxter

Filtrer par domaine, pas par IP. Les agents Lynxter qui exécutent du code (Claude Code, Routines, scripts Cowork) tournent parfois avec un réseau restreint. Action : vérifier que les règles de sortie de ces environnements filtrent sur des noms de domaine via un proxy, et non sur des plages d'IP, puis tester un accès à une URL interdite derrière un CDN partagé.

Couper le web quand il ne sert pas. Le moyen le plus simple de réduire la surface reste de ne pas ouvrir le réseau. Action : utiliser CLAUDE_CODE_DISABLE_WEB_FETCH (Claude Code 2.1.285) sur les postes de support qui n'ont besoin que de la documentation locale.
