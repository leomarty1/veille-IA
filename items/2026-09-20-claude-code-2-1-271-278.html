Contexte étendu

La série va de la 2.1.271 (14 septembre) à la 2.1.278 (19 septembre), soit huit versions en six jours — un rythme conforme aux semaines précédentes, mais avec deux entrées qui ne sont pas de la maintenance. La première est un changement de facturation. L'auto mode s'appuie sur un classifieur qui décide, à chaque appel d'outil, si l'action peut passer sans approbation. Jusqu'à la 2.1.278, ce classifieur tournait à la charge du client sur les comptes API et Enterprise, sur Bedrock, Vertex, Foundry et les gateways : ses tokens étaient facturés. La 2.1.278 en fait, par défaut, un service côté serveur qui ne facture pas cet overhead. La sortie reste possible via CLAUDE_CODE_AUTO_MODE_SERVER=0 sur Bedrock, Vertex, Foundry et gateways, et Claude Code émet un avertissement quand la session retombe sur un chemin facturé. Une ligne Auto mode server apparaît dans /status pour vérifier où tourne le classifieur de la session en cours.

La seconde entrée structurante est la 2.1.277 (18 septembre) : dans un projet sans CLAUDE.md, Claude Code lit désormais AGENTS.md. Le réglage se change sous « Project instructions » dans /config, et le support n'est pas encore là sur Bedrock, Vertex et Foundry. AGENTS.md est la convention que lisent déjà Codex CLI et Cursor ; l'adopter en repli signifie qu'un dépôt n'a plus besoin d'un fichier de consignes par agent. La précédence reste à CLAUDE.md quand les deux existent, donc rien ne bouge sur un dépôt déjà équipé — c'est une convergence d'écosystème, pas une migration.

Le reste de la série est plus dispersé mais touche la sécurité et l'ergonomie des agents. La 2.1.271 introduit des allowed_domains par commande pour Bash, PowerShell et Monitor en auto mode avec sandbox : les hôtes dont une commande a besoin sont examinés avec elle et ouverts pour elle seule, les autres sont refusés — un grain plus fin que l'allowlist globale. La même version ajoute omitClaudeMd en frontmatter d'agent, qui laisse un sous-agent tourner sans les CLAUDE.md utilisateur, projet et local (les fichiers de politique managée restent chargés). La 2.1.275 synchronise vers le terminal les skills et plugins activés sur le compte claude.ai, avec syncClaudeAiSkills: false et syncClaudeAiPlugins: false pour s'en abstraire. Enfin, la 2.1.276 illustre le coût du rythme : une régression introduite la veille par la 2.1.275 faisait échouer toutes les requêtes derrière un ANTHROPIC_BASE_URL pointant un proxy ou un gateway, corrigée en 24 h par une version dédiée.

🎯 Pourquoi c'est important pour Lynxter

La facturation du classifieur est la ligne à vérifier, pas à lire. Cette routine de veille enchaîne des dizaines d'appels d'outils en auto mode chaque lundi, et l'overhead de classification était jusqu'ici une ligne de coût invisible parce que noyée dans le total. Lance /status dans une session Claude Code à jour et lis la ligne Auto mode server : si elle indique le serveur, l'overhead a disparu sans que tu aies rien changé. Si elle indique un chemin facturé, cherche un CLAUDE_CODE_AUTO_MODE_SERVER=0 traînant dans un environnement ou une configuration managée. Le gain n'est pas chiffrable de l'extérieur — Anthropic ne publie pas le volume de tokens du classifieur — donc la mesure utile est un avant/après sur la facture d'un run complet de la routine.

AGENTS.md est une assurance de portabilité à noter, pas une conversion à faire. Le dépôt veille-IA a un CLAUDE.md qui reste prioritaire : ne touche à rien. La conséquence est pour la suite — le jour où tu veux comparer Claude Code à Codex CLI ou Cursor sur une base firmware S300X/S600D, les consignes projet n'ont plus à être réécrites dans trois formats. Concrètement, sur le prochain dépôt que tu équipes, écris AGENTS.md plutôt que CLAUDE.md si tu veux garder la porte ouverte, en gardant la réserve que le support manque encore sur Bedrock, Vertex et Foundry.

allowed_domains par commande mérite un essai sur la routine elle-même. Le pre-flight de cette routine teste l'egress et se heurte régulièrement à un proxy restrictif ; une allowlist par commande permet d'accorder code.claude.com et platform.claude.com à la commande scout.js seule, sans ouvrir ces hôtes à tout le reste de la session. À tester au prochain run en sandbox, en mesurant une seule chose : est-ce que le scout passe toujours, et est-ce que les autres commandes se voient bien refuser les hôtes non déclarés. Et garde en tête l'enseignement de la 2.1.276 — à huit versions par semaine, une régression peut casser toute session derrière un gateway pendant 24 h, ce qui est un argument pour ne pas mettre à jour Claude Code le matin d'un run de publication.
