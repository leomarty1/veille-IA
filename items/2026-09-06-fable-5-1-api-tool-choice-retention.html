Contexte étendu

L'annonce du 1er septembre parle de benchmarks et de prix. Les release notes de la plateforme, publiées le même jour, parlent de ce qui casse. Premier point, le plus concret pour un code existant : sur Fable 5.1 et Mythos 5.1, tool_choice en mode any (forcer un appel d'outil) ou tool (forcer un outil précis) renvoie une erreur 400. Seuls auto et none subsistent. La voie indiquée pour obtenir un input strictement conforme au schéma est le strict tool use ou les structured outputs — un changement de contrat, pas un réglage.

Deuxième point, plus subtil : le thinking devient lié à l'historique. Un bloc de thinking produit par Fable 5.1 n'est lisible que par Fable 5.1 ou un modèle plus récent (l'inverse reste vrai : 5.1 accepte les blocs d'Opus 5, Fable 5, Mythos 5 et antérieurs). Surtout, pour les comptes créés à partir du 31 août 2026, l'API vérifie que rien n'a changé avant un bloc rejoué — system prompt, outils, message antérieur — et renvoie 400 sinon. Le header beta thinking-binding-controls-2026-08-01 permet de choisir entre rejet et abandon silencieux, avec un champ input_transformations qui liste ce qui a été retiré. Trois betas accompagnent le modèle : l'effort modifiable par message via output_config.effort dans un message system en cours de conversation (cache préservé), les messages système à portée d'un tour (clear_at: "next_user_message", sans coût de tokens ensuite, sans invalider le cache), et thinking.display: "updates" qui renvoie les courts points d'avancement entre appels d'outils comme texte.

Troisième point, celui qui compte en RFP : les deux modèles exigent 30 jours de rétention et ne sont pas disponibles sous zero data retention sans autorisation expresse d'Anthropic — même règle que Fable 5, reconduite. S'y ajoutent le watermark textuel sur toute sortie et des Content Credentials C2PA sur les fichiers image, vidéo et audio produits via code execution et récupérés par la Files API, sans changement de requête. Enfin, les guides des endpoints Enterprise (Admin API, Analytics, Compliance) affichent désormais le header anthropic-version, à envoyer sur chaque appel. À titre de comparaison, GPT-6 Astra, sorti deux jours plus tard, documente un contexte de 1.05M sans clause de rétention par modèle publiée dans ses notes de version.

🛠 Pourquoi c'est utile à savoir pour Lynxter

Deux vérifications à faire avant de basculer un agent sur Fable 5.1. D'abord chercher tout tool_choice en any ou tool dans les prompts de support et les Routines Cowork : chacun devient une erreur 400 au premier appel. Le remplacement est le strict tool use, qui garantit la conformité au schéma sans forcer l'appel. Ensuite, si une session rejoue des blocs de thinking après avoir modifié la liste d'outils (un serveur MCP ajouté en cours de route, typiquement), le comportement change pour les comptes récents : tester avec le header beta plutôt que de découvrir le 400 en production.

La rétention de 30 jours corrige l'argumentaire EFS de ce brief. Enterprise Frontier Safeguards déplace la détection d'abus chez le client tout en gardant la ZDR — mais Fable 5.1 et Mythos 5.1 ne sont pas éligibles à la ZDR sans accord exprès d'Anthropic. Pour un client industriel qui exige zéro rétention, la réponse honnête est donc : soit un modèle éligible ZDR (Opus 5, Sonnet 5), soit une autorisation Anthropic à obtenir avant contractualisation. À inscrire tel quel dans le paragraphe type de réponse à appel d'offres.
