Anthropic refacture les refus sur trois catégories et retire les noms de fichiers de l'Activity Feed

Contexte étendu

Le premier changement est une ligne de facture. Anthropic reprend la facturation des refus qui surviennent avant toute sortie lorsque stop_details.category vaut "bio", "frontier_llm" ou "reasoning_extraction", en justifiant le choix par le faible volume de faux positifs mesuré sur ces trois catégories. Ces requêtes sont facturées comme n'importe quelle autre, au tarif du modèle qui les a traitées. Les refus intervenant en cours de flux étaient déjà facturés, les refus avant sortie dans les autres catégories restent gratuits, et le crédit de repli est inchangé. Le changement s'applique sur toutes les plateformes.

Le second touche l'audit. L'Activity Feed de la Compliance API cesse de renvoyer les noms de fichiers, les noms de documents de projet et les titres d'artifacts : les champs filename et title des activités correspondantes sont désormais toujours vides ou omis. Le point important est la portée : le retrait s'applique aussi aux activités enregistrées avant ce changement, donc à l'historique déjà collecté. Pour retrouver un nom ou un titre à partir de l'identifiant porté par l'activité, il faut passer par une clé d'accès Compliance dotée du scope read:compliance_user_data.

Dans le même lot, les endpoints de sessions locales de la Compliance API sortent de bêta pour les sessions Claude for Microsoft 365 dans Excel, PowerPoint, Word et Outlook — les valeurs de product_surface commençant par office_agents.

🛠 Pourquoi c'est utile à savoir pour Lynxter

Le retrait rétroactif des noms de fichiers est le point à traiter en priorité, parce qu'il casse des choses déjà en place. Tout tableau de bord, export ou procédure de conformité qui affichait un nom de fichier depuis l'Activity Feed affiche désormais du vide, y compris sur des données historiques déjà ingérées. Action : vérifie si quelque chose côté Lynxter consomme l'Activity Feed, et si oui, décide soit de demander une clé avec le scope read:compliance_user_data, soit d'assumer de ne plus afficher que des identifiants — mais ne laisse pas un champ se vider sans que personne ne s'en aperçoive.

La facturation des refus est une ligne à surveiller, pas une ligne à craindre. Sur un usage de support technique en impression 3D, les catégories concernées — biologie, modèles frontière, extraction de raisonnement — ne devraient pratiquement jamais se déclencher ; le risque réel est un faux positif isolé sur un prompt mal tourné, désormais facturé au tarif Opus 5.5. Action : ajoute un compteur des réponses portant un stop_details.category dans la télémétrie du pipeline, et regarde le chiffre dans un mois plutôt que de spéculer maintenant.

La GA des sessions locales sur Microsoft 365 est à noter pour plus tard. Si des postes Lynxter utilisent Claude dans Excel, Word ou Outlook, les sessions correspondantes deviennent auditables via un endpoint stable — c'est la condition pour pouvoir répondre à une question de conformité sur l'usage de l'IA en interne. Action : pas d'urgence, mais range l'information avec l'argumentaire RFP sur la conformité, où la question « pouvez-vous auditer l'usage de l'IA par vos équipes ? » revient régulièrement.
