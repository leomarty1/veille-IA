Contexte étendu

Les deux corrections de sécurité de la 2.1.251 touchent la même classe de défaut : la frontière entre ce qu'un agent est autorisé à toucher et ce qu'il touche réellement. Les outils fichiers suivaient les liens symboliques, ce qui permettait de lire ou d'écrire hors des emplacements approuvés — sur un dépôt contenant un lien vers un montage réseau ou un dossier de configuration, l'autorisation « travaille dans ce répertoire » ne tenait plus. Le second défaut est une traversée de chemin classique : des commandes de plugin pointaient hors du répertoire du plugin. Aucun des deux n'exige une manipulation exotique pour se déclencher, et tous deux concernent des postes où Claude Code tourne souvent sans surveillance rapprochée.

Le drapeau --restricted introduit en 2.1.248 est la nouveauté la plus structurante pour qui déploie des agents contraints : il retire les outils intégrés — commandes, exécution de code, WebFetch. Jusqu'ici, restreindre un agent supposait d'empiler des règles de permission ; le drapeau donne un profil serré en un seul argument. Dans la même version, experimental.cacheTtl passe dans le frontmatter d'agent et permet de fixer la durée de cache de prompt agent par agent — utile quand un agent tourne en rafale courte et un autre en session longue. Le correctif qui a le plus d'effet mesurable est ailleurs : un manque de cache de prompt survenant environ une fois par heure dans les sessions longues, causé par un re-rendu des définitions d'outils. Sur un agent à gros prompt système qui tourne toute la journée, un manque de cache horaire se paie en tokens d'entrée pleins tarif, plusieurs fois par jour.

Le reste des trois versions consolide l'outillage d'observation et d'orchestration. La 2.1.251 ajoute une barre de plafond de dépense dans /usage avec un champ rate_limits.spend_limit, et des métriques de cache de prompt par session dans /cost — c'est-à-dire, enfin, de quoi vérifier soi-même que le cache fait son travail plutôt que de le déduire de la facture. Les hooks PreModelSwitch et PostModelSwitch permettent de reprendre la main sur les bascules de modèle. Côté corrections, la liste est dense : conversations bloquées sur « text content blocks must be non-empty » après un tour de pure réflexion, requêtes Opus 5 en effort xhigh ou max qui échouaient avec la réflexion désactivée, lenteur du TUI avec beaucoup de sous-agents parallèles, réponse finale d'un coéquipier qui n'atteignait pas le chef d'équipe dans les agent teams, et sessions Claude Desktop et Cowork qui disparaissaient au bout de 30 jours.

🎯 Pourquoi c'est important pour Lynxter

Mettre à jour vers 2.1.251, et vérifier la version sur les postes non surveillés. Les deux évasions de chemin ne sont pas des défauts théoriques : un dépôt de travail contient très souvent des liens symboliques vers des dossiers partagés ou des configurations hors périmètre, et c'est précisément le cas que le correctif adresse. La règle pratique : sur toute machine où Claude Code tourne en tâche de fond ou en mode automatique, la version installée fait partie de la surface de sécurité au même titre que les permissions accordées.

--restricted est le profil qui manquait pour un agent SAV. Un assistant qui lit la documentation machine, cherche dans l'historique des interventions et rédige une réponse client n'a besoin ni d'un shell, ni d'exécution de code, ni de WebFetch. Jusqu'ici, ce profil se construisait à coups de règles de permission qu'il fallait maintenir ; il tient désormais dans un drapeau. À combiner avec experimental.cacheTtl : un agent de support à gros prompt système gagne à garder un cache long, là où un agent de build lancé en rafale n'en a pas l'usage. Le correctif du manque de cache horaire joue dans le même sens — vérifiez l'effet directement avec les nouvelles métriques de cache par session de /cost, plutôt qu'en attendant la facture du mois.

Comparaison utile pour situer la cadence : Claude Code a sorti huit versions en sept jours la semaine précédente (2.1.234 → 2.1.241) et trois en deux jours cette semaine. À ce rythme, épingler une version dans un script d'installation devient un choix qui se justifie — mais avec une revue du changelog au moins hebdomadaire, sans quoi un correctif de sécurité comme celui de la 2.1.251 peut rester non appliqué pendant des semaines sur un parc.
