Contexte étendu

Un mois après la sortie de l'app iOS du 29 juin, Cursor publie le 29 juillet une version pensée pour l'iPad, ouverte à tous les plans payants. Le layout exploite la surface disponible plutôt que d'étirer l'interface téléphone : side chats épinglés en sidebar pour surveiller plusieurs agents s'exécutant en parallèle, split screen permettant de garder une review ouverte à côté d'un chat, et diffs de fichiers rendus intégralement au lieu d'être tronqués.

Deux ajouts sont communs à l'iPhone et à l'iPad, et c'est là que se trouve l'idée intéressante. Le premier est l'Inbox : une vue unique qui sépare ce qui tourne, ce qui attend une action humaine et les PR en attente de review. Le second est une expérience de review couvrant la PR entière — commentaires, checks CI, approbations, ajout ou changement de reviewers — avec la possibilité de prompter l'agent pour qu'il résolve les commentaires en place. Le markup accepte une capture d'écran commentée avec ancrage sur un point précis, et l'annotation directe à l'Apple Pencil.

Côté plomberie, deux SCM s'ajoutent — Bitbucket et Azure DevOps — avec import de dépôts depuis GitLab, Bitbucket ou Azure DevOps, et les sessions multi-PR sont corrigées : un chat qui produit plusieurs PR permet désormais de toutes les ouvrir, plus seulement la dernière. Il n'y a toujours aucune app Android, ce qui limite le pattern aux flottes Apple.

🛠 Pourquoi c'est utile à savoir pour Lynxter

Le réutilisable ici n'est pas l'app, c'est le pattern de supervision. Un Inbox qui distingue explicitement « en cours » de « attend un arbitrage humain » est précisément ce qui manque quand plusieurs runs Claude Code longs tournent en parallèle : aujourd'hui, savoir lequel est bloqué sur une question demande d'ouvrir chaque session. La même distinction est reproductible côté maison — un fichier d'état ou un canal de notification par run, avec deux états seulement, tourne / attend quelqu'un. C'est peu de travail pour un gain net dès qu'on dépasse deux agents simultanés.

Le cas d'usage terrain est concret. Un technicien en intervention sur S300X/S600D qui doit valider une PR de documentation ou une modification de procédure n'a pas de poste fixe sous la main. Une review complète depuis tablette — voir le diff entier, laisser un commentaire ancré, demander à l'agent de corriger, approuver — supprime le délai entre l'intervention et la mise à jour de la doc, moment où l'information est encore fraîche. À tester tel quel sur un cycle de rédaction de procédure avant d'en tirer une règle.

Mais rien qui justifie une migration d'outillage. L'écosystème Cursor reste secondaire pour nous, et l'absence d'app Android exclut une partie du parc. La lecture correcte est concurrentielle : Cursor investit l'ergonomie de supervision multi-agents, terrain où Claude Code est aujourd'hui plus fruste. C'est le genre d'écart qui se comble par tooling maison plutôt que par changement de plateforme.
