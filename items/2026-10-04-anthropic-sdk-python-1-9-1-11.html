Contexte étendu

La 1.9.0 (28 septembre) accompagne Sonnet 5.5 : type de thinking between_tools, identifiant claude-sonnet-5-5, champs include_inherited et source sur les rate limits de workspace, cache diagnostics en GA sur Message et MessageCreateParams, et option pour exécuter les appels d'outils pendant que la réponse streame plutôt qu'à la fin. La 1.10.0 (30 septembre) élargit l'Admin API : analytics Claude Enterprise, limites de dépense, groupes et rôles RBAC, rapports d'usage et de coût par utilisateur, gestion des Plugins et Plugin Marketplaces ; les endpoints Organization API passent en GA.

Côté agents, la 1.10.0 ajoute un stop reason refusal avec stop_details sur les événements idle des sessions Managed Agents, et la bêta MCP tunnels gagne un objet transport en lecture seule et un relay token à usage unique. La 1.11.0, le même jour, ajoute l'endpoint de liste des spend limits et marque Sonnet 4.5 comme déprécié. Pour comparaison, le SDK OpenAI n'expose pas de rapport de coût par utilisateur dans son client ; il faut passer par l'Usage API de l'organisation.

🛠 Pourquoi c'est utile à savoir pour Lynxter

Monter le SDK avant la migration Sonnet 5.5. Sans la 1.9.0, le type between_tools n'existe pas côté client typé. Action : passer les environnements Python des scripts Cowork et de la Routine veille en 1.11.0, et lancer les tests sur Sonnet 5.5 dans la foulée.

Chiffrer le coût par personne. Les rapports de coût par utilisateur et les spend limits rendent mesurable ce qui ne l'était qu'au niveau organisation. Action : extraire un mois de coût par utilisateur via l'Admin API, poser une spend limit par poste de support, et comparer au budget prévu pour l'équipe.
