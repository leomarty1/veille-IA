Contexte étendu

OpenAI livre le 20 juillet une vague de GA côté Codex : rendu de diagrammes Mermaid inline dans les transcripts de tâches, formulaires interactifs dans les tâches (points de collecte human-in-the-loop où l'agent demande une saisie structurée avant de continuer), restauration des prompts non envoyés au changement de tâche/host/workspace, et tri des listes de tâches par activité récente avec affichage des hosts indisponibles. Ces items sont distincts des releases Codex CLI 0.142/0.143 déjà couvertes le 20 juil. (délégation multi-agents, budgets de tokens par rollout, web search indexée).

Côté plateforme API, l'ajout structurant est le système de spend limits mensuels à deux niveaux — organisation ET projet. Deux modes : alerte (notification e-mail + bandeau dashboard au seuil, mais la clé continue de facturer) ou hard cap (les requêtes API échouent au dépassement du plafond). L'usage est ventilé par projet, ce qui permet d'attribuer et de plafonner la dépense au grain du projet plutôt qu'au grain de l'organisation entière.

Le sourcing de cet item est faible côté première main : le changelog officiel developers.openai.com/codex/changelog et les release notes API n'étaient pas fetchables (egress openai.com/developers.openai.com bloqué, 403 proxy), et les secondaires disponibles sont principalement des trackers de changelog. La fonctionnalité spend limits est néanmoins largement documentée et cohérente avec la trajectoire FinOps de la plateforme API OpenAI.

🛠 Pourquoi c'est utile à savoir pour Lynxter

Les spend limits par projet sont le garde-fou FinOps qui manquait pour cloisonner staging et prod. Sur une stack agent, le risque n°1 en coût est un script d'automatisation qui s'emballe (boucle mal bornée, retry agressif). Un plafond mensuel par projet en mode hard cap garantit qu'un run de test qui dérape épuise le budget du projet staging et fait échouer ses propres requêtes — sans jamais toucher les crédits du projet production. Si Lynxter benchmarke Codex en parallèle de Claude Code, câble immédiatement un projet dédié avec hard cap bas pour les expérimentations, et réserve le mode alerte au projet prod où couper les requêtes serait pire que dépasser légèrement.

Les formulaires interactifs rapprochent Codex des boucles d'approbation que tu benchmarkes déjà. Le pattern human-in-the-loop de Codex (l'agent s'arrête et demande une saisie structurée) est l'équivalent des points d'approbation de Claude Code — utile à comparer en tête-à-tête sur un workflow support réel pour juger de l'ergonomie et de la fiabilité des deux. Le rendu Mermaid inline, lui, est un confort de lecture pour visualiser un plan d'agent ou un flux de diagnostic directement dans le transcript, sans outil externe. À noter comme signal, pas comme raison de migrer : le cœur du stack Lynxter reste Claude Code.
