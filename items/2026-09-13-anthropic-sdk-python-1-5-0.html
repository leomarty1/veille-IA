Contexte étendu

La 1.5.0 est une version de suivi d'API plus qu'une version de bibliothèque : l'essentiel du lot reflète des capacités serveur livrées le même jour. Les permissions d'outils en mode auto pour les Managed Agents sont la contrepartie cliente de la politique annoncée dans les release notes de la plateforme. Le montage de dépôts GitHub publics sans jeton d'autorisation dans une session Managed Agents supprime une friction concrète : jusqu'ici, faire lire un dépôt public à un agent hébergé imposait de lui fournir un jeton, donc d'en créer un, de le faire tourner et de le révoquer. Le code d'erreur content_too_large ajouté à l'outil web_fetch rend distinguable un cas jusque-là noyé dans les erreurs génériques. La valeur beta user-profiles-2026-09-04, avec external_user_details, ouvre le rattachement d'un appel à un utilisateur externe identifié.

Côté ergonomie, les outils peuvent maintenant être passés comme objets directement à messages.create, parse, stream et count_tokens, sans conversion manuelle préalable en dictionnaire. Message.to_param() et BetaMessage.to_param() font le chemin inverse et renvoient la forme paramétrable d'un message reçu — utile pour rejouer ou réinjecter un tour sans le reconstruire à la main. extra_body est désormais fusionné avant l'exécution des hooks client, ce qui change l'ordre observable pour qui instrumente ses appels. L'option de requête idempotency, inutilisée, est retirée.

Deux correctifs relèvent de la sécurité plutôt que du confort. Le SDK refuse désormais un fichier de credentials accessible par le groupe ou par les autres — même logique qu'un client SSH qui refuse une clé privée en mode 644, et changement de comportement à anticiper si un déploiement s'appuyait sur des permissions larges. De nouvelles exceptions CredentialsError et IdentityTokenFileError rendent ces échecs distinguables plutôt que génériques. Le second correctif empêche le JSON partiel d'entrée d'outil d'apparaître sur les blocs de contenu pendant le streaming : un consommateur qui lisait ces blocs au fil de l'eau pouvait voir des fragments d'arguments d'outil non finalisés. parsed_output est par ailleurs exclu des blocs de texte sérialisés.

🛠 Pourquoi c'est utile à savoir pour Lynxter

Le refus des credentials lisibles par le groupe est le point à vérifier avant toute montée de version. Un déploiement qui pose un fichier de credentials via un script d'installation ou une image conteneur hérite souvent de permissions 644 sans que personne ne l'ait décidé. Avec la 1.5.0, ce déploiement cesse de fonctionner, et l'erreur — désormais une CredentialsError explicite — apparaîtra au démarrage. À faire avant de monter : un stat sur chaque fichier de credentials des machines qui font tourner des scripts Anthropic, et un chmod 600 là où c'est nécessaire. C'est cinq minutes de vérification contre une routine de nuit qui échoue sans personne pour la relancer.

Le montage de dépôts publics sans jeton simplifie un cas d'usage que tu as déjà. Faire analyser par un agent hébergé un dépôt public — documentation d'un slicer, bibliothèque de profils d'impression, SDK d'un fournisseur de matériau — imposait de créer un jeton GitHub dédié pour un accès qui n'en demandait pas. Un jeton de moins, c'est une rotation de moins et un secret de moins à surveiller. À faire : passe en revue les jetons GitHub créés pour des sessions d'agent et révoque ceux qui ne servaient qu'à lire du public. Réserve : cela ne change rien pour les dépôts privés Lynxter, qui continuent d'exiger une autorisation en bonne et due forme.
