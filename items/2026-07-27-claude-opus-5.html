Claude Opus 5 — nouveau défaut Opus, pricing inchangé $5/$25, contexte 1M, 79,2 % SWE-bench Pro et toggle d'effort

Contexte étendu

Anthropic sort Claude Opus 5 le 24 juillet 2026 au même pricing qu'Opus 4.8 ($5 input / $25 output par M tokens), contexte 1M tokens. Le saut se concentre sur les benchmarks agentiques : 79,2 % sur SWE-bench Pro, soit +10 pts vs Opus 4.8 (69,2 %) sur le benchmark le plus représentatif des tâches longues, multi-fichiers et mal spécifiées ; et ~96 % sur SWE-bench Verified, une quasi-saturation qui place Opus 5 devant Fable 5 (~95 %), le heavyweight frontière. Anthropic positionne explicitement Opus 5 comme approchant l'intelligence de Fable 5 à environ la moitié du prix.

Au-delà du code, Opus 5 pousse sur le raisonnement général et l'agentique large : 43,3 % sur Frontier-Bench en effort max (44,4 % en xhigh) et 30,2 % sur ARC-AGI-3, soit environ 3× le score du modèle suivant sur ce benchmark de raisonnement abstrait. La nouveauté d'usage est le toggle d'effort : un curseur low→high assorti d'un palier max qui arbitre explicitement entre profondeur de raisonnement et coût en tokens — l'équivalent d'un dial de reasoning exposé au niveau de l'appel, là où Opus 4.8 gérait ça de manière plus opaque.

Le fast mode reste ~2,5× plus rapide pour un prix doublé ($10/$50 par M tokens, confirmé par le changelog Claude Code v2.1.219). Opus 5 devient le nouveau défaut Opus dans Claude Code (v2.1.219, sortie le même jour) et est disponible via l'API Messages. Face à la concurrence de la fenêtre : DeepSeek V4-Pro plafonne à 80,6 % SWE-bench Verified (meilleure entrée open weights mais ~16 pts sous Opus 5 sur Verified), et GPT-5.6 Sol Ultra (couvert le 20 juil.) était à 91,9 % Terminal-Bench — Opus 5 conserve l'avance sur le SWE-bench Pro, le terrain le plus proche du travail d'ingénierie réel.

🎯 Pourquoi c'est important pour Lynxter

Upgrade zéro-friction du stack agent Lynxter. Pricing inchangé, bascule automatique en défaut dans Claude Code : tes Routines Cowork et sessions Claude Code passent sur Opus 5 sans action ni renégociation de budget. Le gain de +10 pts sur SWE-bench Pro touche directement ton terrain — audit firmware S300X, migration de scripts de calibration, diagnostic support multi-fichiers — là où le Verified (déjà ~saturé) n'apportait plus de signal. Action immédiate : relance un run de diagnostic firmware ou une migration de scripts que tu avais laissé de côté sous Opus 4.8 faute de fiabilité, et mesure le taux de réussite sur les tâches multi-fichiers.

Le toggle d'effort est ton nouveau levier FinOps par classe de tâche. Sur les boucles agentiques longues et peu critiques (triage de tickets entrants, déduplication de base de connaissance, pré-traitement RAG de datasheets techniques, génération de brouillons de réponses support), passe en effort low pour couper le coût par tâche à budget constant ; réserve max aux audits où la profondeur de raisonnement conditionne la justesse (analyse de dérive thermique sur profils S600D, recherche cross-fichiers dans la base de calibration). Test cette semaine : prends une Routine qui tourne > 5 min, compare effort low vs défaut sur latence, qualité subjective (note 1-10) et tokens consommés, puis fige un palier par type de Routine dans ta config Cowork.

Consolide l'argumentaire fournisseur. Opus 5 à pricing inchangé conforte le pari Claude comme stack principal : pas de discontinuité, capacité frontière maintenue face à Fable 5 pour ~la moitié du prix, et une avance sur SWE-bench Pro que la concurrence open weights (DeepSeek V4 à 80,6 % Verified, ~1/6 du prix mais loin sur le Pro) ne rattrape pas sur les tâches complexes. Pour les workflows critiques (support client, génération de RFP, parsing de logs machine), garde Opus 5 ; réserve l'exploration open weights / Flash-Lite aux étapes haut-débit peu critiques en offload, sans migrer le cœur du stack.
