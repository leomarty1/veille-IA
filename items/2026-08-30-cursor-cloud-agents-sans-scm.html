Contexte étendu

Jusqu'ici, lancer un cloud agent Cursor supposait un dépôt et donc un fournisseur SCM connecté — GitHub le plus souvent. C'est une friction qui n'a l'air de rien mais qui tue l'usage exploratoire : pour tester une idée en dix minutes, personne ne crée un dépôt d'abord. Depuis le 27 août, on peut lancer un prompt immédiatement, puis choisir « Start from scratch » dans le sélecteur de dépôt pour sauvegarder le travail dans un dépôt Cursor Origin. Cursor referme ainsi la boucle sur son propre hébergement de code, lancé en beta le 17 août pour tous les plans payants.

Deux ajouts transforment l'agent en environnement de travail complet plutôt qu'en producteur de diffs. Cursor redirige le port de l'environnement vivant du cloud agent directement vers le navigateur : on prévisualise ce que l'agent construit pendant qu'il le construit, sans cloner ni lancer quoi que ce soit en local. Et un compte Vercel connecté permet de publier en un clic pour obtenir une URL en ligne. Le chemin complet — prompt, code, prévisualisation, publication — tient dans le produit.

La séquence de la quinzaine se lit d'un bloc et éclaire la direction : 17 août, Cursor Origin en beta plus les Builds pour cloud agents (environnements préparés en arrière-plan, builds réussis gardés au chaud) ; 19 août, améliorations du harness pour des agents toujours actifs, capables de tenir un objectif jusqu'à ce qu'il soit atteint, de réagir à des événements et de rester sur les rails en session longue — surveiller des PR, suivre un fil Slack, exécuter des tâches planifiées ; 27 août, suppression de la dernière dépendance externe au démarrage. Cursor construit une boucle fermée où l'agent n'a besoin d'aucun outil tiers pour aller du prompt à l'URL en ligne.

🛠 Pourquoi c'est utile à savoir pour Lynxter

L'intérêt pour Lynxter est de benchmark concurrentiel plutôt que d'adoption. La direction que prend Cursor — un agent qui démarre sans prérequis, prévisualise son propre travail et publie — est la même que celle de Claude Code côté Anthropic, avec un choix opposé sur l'intégration : Cursor referme la boucle sur ses propres briques (hébergement Origin, Builds, publication Vercel), Claude Code reste ancré dans l'outillage existant du dépôt et de l'organisation.

Le point à retenir concrètement : la redirection de port vers le navigateur est la fonctionnalité la plus imitable et la plus utile du lot. Voir tourner ce que l'agent construit, pendant qu'il le construit, raccourcit la boucle de correction bien plus qu'un rapport de fin de tâche. Si un outillage interne fait travailler des agents sur du code — scripts de production, outils SAV, pages internes —, exposer un aperçu vivant plutôt qu'un diff est le genre d'amélioration à faible coût qui change l'usage réel.
